= sxmml の現行構成と設計

この文書は sxmml を保守・改修する開発者に、構成と変更時の調査先を示す。動作環境は Gauche 0.9.15 である。個々のクラス・手続き・マクロは xref:internal-reference/index.adoc[内部リファレンス] から名前で引ける。利用者が観測する構文・出力・制約は xref:behavior-spec.adoc[外部動作仕様]、製品の目的と責任範囲は xref:product-overview.adoc[製品概要] を参照する。

[[システム境界]]
== システム境界

入力は `sxlc` の引数と、Gauche が評価する Scheme ソースファイルである。ソースには MML 文字列を作る式、トラック・音色・メタデータの定義、モード指定などを記せる。現在の出力は CP932 符号化の PMD 向け MML（`.mml`）および FMP7 向け MML（`.mwi`）、UTF-8 の NSD.Lib 向け MML（`.mml`）、および PMD バイナリ（`.m`）である。

[source,mermaid]
----
flowchart LR
    A[CLI 引数] --> B[sxlc]
    S[Scheme ソース] --> B
    B --> E[環境・トラック登録]
    S --> C[Scheme 式と公開マクロ]
    C --> P[MML / リズム解析]
    P --> H[共通コマンド処理]
    C --> H
    H --> O[中間オブジェクト列]
    O --> E
    E --> Q[出力準備]
    Q --> Z[最適化]
    Z --> G["バックエンド (PMD / FMP7 / NSD.Lib)"]
    Q --> G
    G --> F[生成ファイル]
    B --> X[任意の後処理コマンド]
----

後処理コマンドは `-c` 指定時だけ実行する。生成先と表示名の関係は xref:behavior-spec.adoc#要求との対応と既知の差[外部動作仕様] を参照する。矢印はデータおよび制御の関係を表す。

`sxmml.scm` の `extend` は Gauche のモジュール継承であり、各モジュールでの `use` は他モジュールの束縛を利用するための宣言である。継承・公開名の仕様は link:https://practical-scheme.net/vault/Gauche-0.9.15-refe.pdf[Gauche 0.9.15 Users' Reference, 4.13.4–4.13.5] に従う。MML 記述者向けの操作は xref:sxmml-reference-manual.adoc[MML 記述者向けリファレンス]、開発者向けのクラス・手続きは xref:internal-reference/index.adoc[内部リファレンス] に記す。

[[処理とデータの流れ]]
== 処理とデータの流れ

. `sxlc` の `main` は引数から入力パス・モード・最適化水準・並列数・利用者設定を取得する。利用者設定（`-D`）は局所リストへ収集し、引数検査後・モード選択前に楽曲環境へ登録する。共有表からモード名を解決して選択・初期設定を行った後にソースを `load` する。`-m` 指定時は `sxmml-mode-fixed` を真にしてソース内の `sxmml-mode` マクロを無視する（明示的な `sxmml-mode-select!` による切り替えは可能）。
. 各バックエンドは読み込み時に `<sxmml-mode>` を共有表 `%sxmml-modes` へ登録する。モード情報は正式名・別名・初期設定・出力手続き・既定拡張子を持つ。`sxmml-mode-select!` は楽曲環境の `mode` を更新してから `setup` を実行する（PMD の初期設定は既定トラックを登録する）。
. `compiler.scm` の `mml`・`rhythm` は Scheme 式の結果を `write-tree` で文字列化し、`mml.scm` のパーサーが `command.scm` の共通手続きで文脈更新・IR 生成・tick 集計を行う。IR を生成しない命令は `#f` を返し、`compiler.scm` が収集時に除く。結果はトラックの `compiled-data` に cons 木として登録する。`processor.scm` の `mml-repeat` は反復 IR を共通手続きで直接構築し、`mml-echo`・`mml-delay` はコンパイル結果を加工して登録する。
. `sxlc` は `-o`、登録環境の `default-output-path`、入力名とモード拡張子による既定値の順に出力先を決める（相対パスはカレントディレクトリ基準）。決定済みの出力先・最適化水準・並列数を `make-sxmml-output-environment` へ渡し、`output.scm` が全登録トラックの cons 木を平坦化（NOP 除去）し、`current-ticks` から `total-ticks`・`loop-ticks` を確定する。この段階では最適化しない。
. 最終的な選択モードの `backend` 手続きが出力環境を受け取り、採用トラックの選択・最適化・生成物の出力を行う。
   - **PMD（`pmd-source`・`pmd-binary`）**: 共通の `sxmml-pmd-ir-optimize` が整数要求を解釈し、局所整理・不要再指定の除去・休符結合・反復圧縮（`-O 9` は 2 候補の全幅圧縮）を組み合わせる。反復圧縮の前処理・費用設定・IR 復元は Scheme、固定 IR 比較は CiSE、圧縮探索は Gauche 非依存の C コアが担当する。`pmd-source` は文字列ポートへ本文を生成して使用音色を集め CP932 で書き出し、`pmd-binary` はバイト列バッファを構築して書き出す。
   - **FMP7（`fmp7-source`）**: `sxmml.backend.fmp7` が対応音源トラックをパート順に並べ、反復構造の検査・最適化（`-O 3` 以上で反復圧縮）と LFO 到達状態解析を行う。`sxmml.backend.fmp7-source` が文字列ポートへ書きながら定義番号を採番し、使用定義と本文を CP932・CRLF の `.mwi` として出力する。
   - **NSD.Lib（`nsdlib-source`）**: `sxmml.backend.nsdlib` が非空トラックを音源別に割り当て、反復構造化と LFO 到達状態解析を行う。`sxmml.backend.nsdlib-source` が FDS 波形・エンベロープを命令順で採番し、DPCM をノート番号順の割当表へまとめ、本文と定義を構築して UTF-8・LF の `.mml` として出力する。
   - 各バックエンドとも一時ファイルへ書き出してから出力先へ原子的に置換し、実際の出力先と採用トラック名を持つ `<sxmml-output-result>` を返す。
. `sxlc` は結果の採用トラック名に対応する集計を表示する。出力先が `#f` のバックエンドでは `Translate` 表示と `-c` の後処理を省く。変換失敗時は 0 以外の終了値で終了し、既存の出力ファイルを変更しない。

`classes.scm` は `<sxmml-environment>` と `<sxmml-mml-context>` などのデータ構造を定義する。`<sxmml-environment>` は解像度・各種定義表（`voice` は種類から名前別表を引く 2 段表）・`options` 表・`default-output-path`・選択中モードを保持し、各 `<sxmml-mml-context>` はトラック名・パート・音源種別・解析状態・登録列・tick 統計を保持する。単一 IR オブジェクトのスロット変更でトラック文脈の値が自動で同期するとは限らないため、スロットを直接編集する場合は関連する文脈値も更新する必要がある。詳細は xref:internal-reference/classes.adoc#ref-classes-class-sxmml-mml-context[トラック文脈] を参照する。

[[公開境界と拡張点]]
== 公開境界と拡張点

* Scheme ソース向けの入口は `sxmml` モジュールが `extend` する `mml`・`rhythm`、各種定義・加工マクロ、および `sxmml-mode` とモード操作・利用者設定・既定出力先の公開手続きである。個々の定義は xref:internal-reference/index.adoc[内部リファレンス] を参照する。
* バックエンドの接続点は共有表に登録された `<sxmml-mode>` である。`sxlc` の `use-backend` が `sxmml.backend.*` を読み込み、各バックエンドがモードを登録する。`%mode-list-output` が登録済みモードを正式名順に列挙する。出力先決定と入力ファイルとの同一性検査は `%output-file-resolve` が生成前に行う。
* MML パーサーのコマンド登録は `mml.scm` の命令表（`+*note-command*+`・`+*rhythm-command*+`）、生成時の型別処理は各バックエンド（`pmd-source.scm`・`pmd-binary.scm`・`fmp7-source.scm`・`nsdlib-source.scm`）の分岐にある。新しいコマンドの影響を調べる際は、クラス定義、解析、共通コマンド層、加工・最適化、各バックエンド出力の対応を追う。

[[外部依存と信頼境界]]
== 外部依存と信頼境界

Scheme ソースは `load` で Gauche のコードとして実行される（`sxlc` の `main`）。入力を単なるデータとして隔離する仕組みはないため、信頼できるソースだけを実行する必要がある。Gauche の `load` は link:https://practical-scheme.net/vault/Gauche-0.9.15-refe.pdf[Users' Reference, 6.22.1 Loading Scheme file] を参照する。`-m` は登録済みモードを検索し、`-c` は外部プロセスを起動する。バックエンドの読み込みは実行環境で見つかる `sxmml.backend.*` に依存する。

出力時には各バックエンドが Gauche の文字コード変換（PMD・FMP7 の CP932、NSD.Lib の UTF-8）および一時ファイル作成とリネームを使う。利用する Gauche の機能は link:https://practical-scheme.net/vault/Gauche-0.9.15-refe.pdf[Gauche 0.9.15 Users' Reference の 9.5 Character code conversion、12.40 parser.peg、12.80 Lazy text construction、9.25 Parsing command-line options、High-level process interface] を参照する。

[[制約]]
== 制約

* `environment.scm` の `sxmml-track-clear!` はトラック表全体を消去し、引数は取らない。
* `voice.scm` の `%4op-voice-shape` は `DT2`・`SEG` を含む 12 要素列を作り、`<sxmml-opmn-voice>` 系の音色クラスがこの値列を保持する。PMD 向け出力（`pmd-source`・`pmd-binary`）は OPN にない `DT2` と PMD 音色パラメータにない `SEG` を出力しない。全ての共通音色パラメータが各バックエンドの生成物に現れるとは限らない。
* 共通 IR は各バックエンドがすべての命令・パラメータをそのまま出力できることを保証しない。対応範囲と値の制約はバックエンドごとに検査する。

既知の不具合・未実装・検証不足・仕様確認待ちは link:https://github.com/sayzbrdg/sxmml/issues[課題一覧（GitHub の issue）] を参照する。
