= sxmml 外部動作仕様

sxmml に渡せる入力、生成するファイル、実行時の表示とエラーについて説明する。要求 R-01～R-04 との対応は <<要求との対応と既知の差>> に示す。

以下の例は Gauche 0.9.15 と、link:../README.md#最初の変換[導入手順]に従ってインストールした `sxlc` を使う。入力ファイルを保存するディレクトリはあらかじめ作成する。

[[定義マクロの名前の規則]]
== 定義マクロの名前の規則

音色・LFO・エンベロープの定義名はsymbolまたは数値とし、マクロ展開時にsymbolへそろえる。名前は空でなく、MMLの名前指定に使えない空白・波括弧を含まないものに限る。数値名には整数以外も使え、大文字・小文字は保持する。

種類・メタデータキー・トラック名にはシンボルを指定する。利用者のマクロが生成した識別子も使える。メタデータキーは小文字にそろえ、種類とトラック名は大文字・小文字を区別する。複数トラックを指定する場合も各名前に同じ規則が適用される。

名前の書式に誤りがあると、マクロの展開時にフォーム構文エラーになる。位置を取得できた場合は、診断にファイル名と行番号が付く。この名前の規則は定義マクロに適用する。

[[トラック名の列挙順]]
== トラック名の列挙順

公開手続き `sxmml-track-list` は、現在登録されているトラック名をリストで返す。定義順・名前順を含め、戻り値の順序は保証しない。順序が処理結果に影響する利用側は、必要な順序に並べ替える。

トラック名の列挙順が変わっても、同じ条件で生成したファイルの内容は同じになる（要求 Q-03）。各バックエンドが出力形式に応じてパートの処理順を決める。

[[利用者定義の設定]]
== 利用者定義の設定

`-D 名前 値`／`++--define 名前 値++` は、現在の楽曲環境へ利用者の設定を渡す。名前は symbol で大文字・小文字を区別し、MML の名前制限は適用しない。値は `gauche.parseopt` の `e` 変換で先頭のデータを 1 個読み、`sxlc` では評価しない。例えば `-D gain '9 10'` の値は 9 となる。

CLI の指定は引数の検査後・モード初期設定前に登録し、同じ名前は最後の値を使う。`-m` との位置関係には依存しない。`sxmml-option-get` で参照でき、未登録は `undefined`、登録済みの `#f` は `#f` となる。ソースは `sxmml-option-set!` で後から変更できる。設定は環境ごとに独立し、モード変更でも保持する。

両手続きへ symbol 以外の名前を渡すと `<sxmml-value-error>` となり、本文は `invalid option name: 値 (expected a symbol)` となる。値は Scheme の write 形式で表示する。CLI の引数不足や読み取り時の構文エラーは使用法の誤りとして終了値 2、ソース中の既知の値エラーは終了値 1 となる。診断は標準エラー出力、使用法は標準出力へ出す。

[[入力と実行順]]
== 入力と実行順

`sxlc` は入力ファイル名を一つだけ受け付ける。そのファイルを Gauche の `load` で読み込み、ソース中の Scheme 式を評価する。入力ファイルの拡張子は制限しない。ソースには MML 文字列だけでなく、Scheme 式、`mml` / `rhythm`、各種の定義・設定マクロを含められる。

オプションは入力ファイル名より前に書く。入力ファイル名より後ろに引数があると、ソースを読み込む前に `unexpected argument after the source file: 引数` と使用法を表示し、終了値 2 で終了する。後ろの引数が `-` で始まる場合は、`options must be placed before the source file` も表示する。`-` で始まる入力ファイル名は `++--++` の後に書く。

起動時に利用可能なバックエンドを読み込む。`-m` の指定があれば先にモードを選んで初期設定を行い、ソースを評価する。指定がなければ、ソース内の `(sxmml-mode pmd)` などでモードを選ぶ。ソースの読み込みに失敗した場合は、そのエラーを報告する。読み込みが成功してもモードが未指定なら変換できない。

`-m` を指定すると、ソース内の `sxmml-mode` は位置を添えて警告し、モードを変更しない。名前の検索も行わないが、書式は検査する。引数はシンボル一つに限る。手続き `sxmml-mode-select!` を明示的に呼んだ場合は、選択したモードが変わる。

読み込み後、`sxlc` は出力先を決定し、全トラックの出力環境と最適化レベルをバックエンドに渡す。バックエンドは出力に使うトラックと最適化処理を選ぶ。

同梱のモードと既定の拡張子は xref:product-overview.adoc#機能と責任の境界[出力形式]を参照する。

モード登録表は楽曲間で共有し、選択中のモードは楽曲ごとに保持する。モードを登録しただけでは初期設定を実行しない。選択時には、同じモードを再び選んだ場合も、選択を更新して初期設定を実行する。未登録名を指定すると選択は変わらない。初期設定の途中で失敗した場合は、選択とそれまでに適用した変更が残る。PMD モードを選び直すと、既定トラックの MML はリセットされる。

`sxlc -l` は登録済みモードの正式名と別名を表示する。変換結果と警告には正式名を使う。未登録名を `-m` で指定すると `undefined mode: 名前` と使用法を表示し、終了値は 2 になる。ソース内で未登録名を指定した場合と、モードの初期設定に失敗した場合の終了値は 1 である。

[[cli]]
== CLI

`-D NAME VALUE` / `++--define NAME VALUE++`::
利用者定義の設定値をモード初期設定前に登録する。詳細は <<利用者定義の設定>> を参照する。

`-m MODE` / `++--mode MODE++`::
読み込み前に登録済みの正規名・別名からモードを選択し、初期設定を実行する。未指定ならソース側でモード選択が必要となる。

`-O N` / `++--optimize N++`::
整数を指定する。既定値は 1。PMD では 0 以下で通常の最適化を省き、1 で局所整理、2 でさらに状態追跡と休符結合、3 でさらに反復圧縮を行う。4 以上では展開後の長さが 256 以下の反復を展開してから広い窓で圧縮する。ただし 9 は全幅探索を行う。
+
FMP7 は 2 以下で命令順を保ち、3 で反復圧縮、4 以上で短い反復の展開と圧縮を行う。9 でも 4 と同じ処理になる。NSD.Lib はどのレベルでも整列済みの命令を順に変換する。

`-j N` / `++--jobs N++`::
反復圧縮の並列数上限を正の整数で指定する。不正な値は最適化レベルにかかわらず使用法の誤りとなる。無指定時は利用可能な論理 CPU 数の半分を切り捨てて 1～4 に収め、取得できない場合は 1 とする。並列処理はバックエンドが反復圧縮を選んだ場合に行う。生成物のパート順と採番は逐次時と同じであり、複数トラックの圧縮が失敗した場合の診断順は規定しない。

`-o FILE` / `++--output FILE++`::
出力先を指定する。相対パスの基準は現在のディレクトリである。省略時の選択順は下記のとおり。入力と同じファイルを指す場合は、シンボリックリンク経由でも `output file is the same as the source file: パス` と表示し、終了値 2 で終了する。明示した出力先はソースの読み込み前にも検査する。

`-c COMMAND` / `++--command COMMAND++`::
バックエンドがファイルを生成した場合に、指定コマンドの後ろに出力名を付けて起動する。`COMMAND` の引用・エスケープは指定する側が行う。`COMMAND` だけを引数に分割し、sxmml が追加する出力パスは分割せず末尾の一引数として渡す。空白や `;` を含む名前も一引数になる。`-w` を指定しない場合、後処理の標準出力と標準エラー出力は変換せずに `sxlc` の標準出力と標準エラー出力へそのまま出る。`COMMAND` の字句の誤り（閉じていない引用符など）は、変換の前に使用法の誤りとして検出する。
+
後処理が 0 以外の終了値やシグナルで終了した場合は、標準エラー出力に `post process failed: exit status N` または `post process killed by signal N` と表示し、終了値 3 で終了する。変換は成功しているため生成物は残る。例えば `-c false` を指定すると `sxlc` は終了値 3 となる。

`-w` / `++--wsl++`::
WSL から Windows のツールを後処理に使うための指定である。`-c` と併用すると `wslpath -aw` で後処理に渡すパスを変換し、後処理の標準出力と標準エラー出力を CP932 として読み取って UTF-8 に変換し、`sxlc` の標準出力に表示する。CP932 として復号できないバイト列は置換文字に置き換え、失敗にはしない。外部コマンド `wslpath` が必要であり、`wslpath` が失敗した場合は `post process failed: wslpath:` で始まる通知を表示し、終了値 3 で終了する。

`-l` / `++--list++`::
登録済みモードを正規名順で表示し、別名を同じ行に登録順で表示して終了値 0 で終了する。

`-h` / `++--help++`::
使用法を表示して終了値 0 で終了する。

`-v` / `++--version++`::
パッケージのバージョンを表示して終了値 0 で終了する。

変換に成功すると、バックエンドが返した出力先を `Translate` 行に表示する。出力先が `#f` の場合はこの行と `-c` の起動を省く。どちらの場合も、モードの正式名と指定した最適化レベルを表示し、採用トラックのうち合計 tick 数が正のものを名前順に表示する。

`L` があればループ区間の tick 数も表示する。例えば `(mml G "c8L d8")` は `Track G: total: 24 / loop: 12` となる。tick 数は楽曲内の長さを表す。

ソースでは `sxmml-default-output-path-set!` へ文字列を渡して既定の出力先を指定し、`#f` で解除する。複数回指定した場合は最後の値を採用する。`sxmml-default-output-path-get` は指定した文字列をそのまま返し、初期状態・解除後は `#f` となる。文字列・`#f` 以外を渡すと、`invalid default output path: 17 (expected a string or #f)` のような値エラーとなり、CLI は既知の診断で終了値 1 を返す。

出力先は `-o`、ソースの既定値、入力名とモードによる既定値の順に選ぶ。相対パスはカレントディレクトリを基準とする。選ばれたパスを入力との同一性検査に使い、`-o` で別のパスを選んだ場合は、ソースの既定値が入力自身でも生成できる。

PMD の `-O 9` は、基本整理（局所整理・状態追跡・休符結合）と有限反復の展開を両方の順序で適用し、それぞれ区間全体を探索する。トラックごとに出力 IR 数が少ない方を採用し、同数なら先に基本整理した方を使う。`L` を含む反復と、同じ段に複数の `:` がある反復は展開しない。

全幅探索の計算量は区間長の 3 乗、主要な表の容量は 2 乗に比例する。探索対象が 3,072 要素を超える最初の区間でトラックごとに警告を標準エラーに表示し、処理を続ける。中断するには Ctrl-C を押す。応答がなければ繰り返し押す。Gauche が探索中に強制終了した場合、pmd-source の出力先は置き換わらず、出力先ディレクトリに一時ファイルが残ることがある。

個々の指定値が有効でも、展開後に隣接する相対指定を合成した値が出力形式の範囲を超えると変換エラーになる。例えば pmd-binary の FM では、`++[v*127]2c++` の相対音量は合成すると `+254` となり、1 命令の上限 `+127` を超える。

PMD のバックエンドを直接呼び出した場合、出力環境の出力先が `#f` なら `output file is not specified` という値エラーになる。

[[mml-ソースに記述できる内容]]
== MML ソースに記述できる内容

`++mml TRACK EXPR ...++` は、Scheme 式を評価し、得られた値を MML 文字列に組み立てて通常 MML として登録する。`++rhythm TRACK EXPR ...++` は同様にリズム MML として登録する。両者とも単一の登録済みトラック名、または登録済みトラック名のリストを指定できる。

本文の各式を一度評価し、文字列を一度作って共有する。各トラックの解析文脈で、指定順にコンパイル・登録する。本文なしの形も受理する。トラック名は symbol または identifier とし、書式違反・空の対象リスト・不正な名前は位置付きのフォーム構文エラーで拒否する。式の値がリストなら要素を順に文字列化できる。入力がトラックの構文に合わなければ変換は失敗する。

ソース中の定義・設定マクロとして `define-track`、`rename-track`、`sxmml-resolution`、`define-metadata`、`define-lfo`、`define-envelope`、`define-opn-voice`、`define-opm-voice`、`define-pcm-voice`、`define-waveform`、`sxmml-mode` がある。

`define-metadata` の値は式として評価する。括弧の中に文字列だけを並べる旧書式 `(define-metadata memo ("a" "b"))` は、文字列のリストとして受け付け、標準エラー出力に `++warning: /home/user/song.sxl:12: (define-metadata memo ("..." ...)) is deprecated; use (list "..." ...) or '("..." ...)++` のように位置を示す警告を表示する。警告は変換の成否に影響しない。各定義の書式とバックエンドでの扱いは xref:sxmml-reference-manual.adoc[MML 記述者向けリファレンス]を参照する。

`define-lfo`・`define-envelope` は `++(define-lfo id [type] value)++`・`++(define-envelope id [type] value)++` の形を取り、名前・種類はリテラル、種類の省略時は `default` とする。標準の `list`・`quote`・`quasiquote` による値の式と変数参照を一度評価して登録する。識別は綴りではなく束縛を比較するため、例えば利用者が `list` を 1 に束縛した `(list 2 3 4)` は旧書式として扱う。

旧書式は各要素を評価してリストにまとめ、展開時に `++warning: /home/user/song.sxl:12: (define-lfo L1 (value ...)) is deprecated; use (list value ...)++` の形式で標準エラー出力へ警告する。エンベロープも同様である。位置がなければ位置だけを省き、実行のたびに警告を繰り返さない。警告自体は成否を変えない。一般の手続き呼び出し形も移行期間中は旧書式になるため、計算には登録手続きを使う。廃止時期は未定である。

両登録手続きは、空リストを含むプロパーリストだけを受け付け、未使用の定義も登録時に外形を検査する。違反は `invalid LFO values: L1 is 17 (expected a proper list)` や `invalid envelope values: E1 is (1 . 2) (expected a proper list)` の値エラーとなり、登録済みの値は変更しない。マクロ経由では定義位置を付け、CLI は終了値 1 で報告する。

引数の過不足などは `++invalid define-lfo form: expected (define-lfo id [type] value)++` のフォーム構文エラーとする。エンベロープも同じ形で表示する。値の式で発生した未知の例外は Gauche が報告する。

通常 MML では、`c d e f g a b` の音符、`r` の休符、`/` のポルタメント、音長・音高の `l o > < q &`、音量・定位の `v v* ) ( p`、移調・テンポ等の `K K$ K* t T D`、制御・定義参照の `++L [ : ] @ E M Mt Mf w P++` を使える。音符と休符には分母指定、`%` による tick 指定、付点、`&` による長さの加算がある。解像度の既定値は 24、音長の既定の分母は 4、オクターブの初期値は 4。`(mml G "c8r8")` は既定の解像度で合計 24 tick となる。個々のコマンドの効果は対象トラックと生成モードにも依存する。

リズム MML は PMD 向けモードで使用する。`@` で `b s t c h i` から一つ以上の楽器を選んで発音し、`!` で指定楽器を止める。波括弧付きの楽器指定も受ける。`++r V v p ) ( l L [ : ]++` も使える。`V` は全体の音量指定、`v`・`p`・`)`・`(` は楽器別の指定である。`(rhythm L "@b8r8")` は合計 24 tick となり、PMD 向けファイルにリズム行を生成する。

通常 MML とリズム MML の `%` 指定は、正の整数を十進数字で受け付ける。先頭の 0 は許され、`%01` は 1 tick、`%00012` は 12 tick となる。音符・休符・リズム発音・ポルタメントと `&` による長さの加算で同じ制約が適用される。`%0`、`%00` など値が 0 の指定、符号付き数、小数、数字の省略はエラーになる。0 tick・分母 0・不正な楽器指定の失敗例は <<失敗条件と境界値>> に示す。

MML オブジェクトを加工する公開マクロとして `mml-repeat`、`mml-echo`、`mml-delay` がある。`mml-echo` が受けるトラックは単一名である。

`mml-delay` は音符の後の休符を利用して直前の音を再発音する。`mml-repeat` の三本文形式では第三節の本文を反復後に置く。複数トラック形では第三節の先頭で脱出対象トラックを指定する。

`mml-repeat` の回数式は反復終了の直前に一度だけ評価し、全対象トラックで共有する。二本文・三本文形式では第二節の後、第三節の前となる。本文は `begin` へ並べ、新しいローカルスコープで囲まない。不正な回数は `invalid repeat count: 値 (expected a positive exact integer)` の値エラーとし、フォーム位置とトラック情報を添える。

`mml-echo`・`mml-delay` の括弧の中の値も式として評価し、変換時に検査する。`mml-delay` は 3 値と本文の各式をそれぞれ一度評価し、MML 文字列を一度作って共有する。各トラックを指定順に個別コンパイル・加工・登録する。共有する式同士の評価順は保証しない。

オブジェクトの slot の直接変更では関連する文脈値が更新されない場合がある。直接編集する場合は、関連する文脈値も利用者が更新する必要がある。

通常・リズム MML の反復回数は正の正確な整数とし、十進の数字列で書く。波括弧で囲んだ数字列や、ゼロ埋めした正の回数も受理する。`++[ab]1++` は `ab`、`++[a:b]1++` は `a` と同じ意味であり、`-O 0` では反復を保持する。回数 0 は、脱出（`:`）の有無や出力モードによらず、構文解釈時に変換の失敗とする。反復の後の既定音長・オクターブ・`K$` の移調値は、脱出のある反復では `:` の位置、脱出のない反復では本文末尾の設定を引き継ぐ。

通常・リズム共通で `L` は 1 トラックに 1 個までとし、同じトラックへの複数回の登録にまたがる 2 個目も拒否する。別トラックでは独立して使用できる。pmd-source・pmd-binary は、直接渡された IR にも複数のループ開始があれば生成を失敗させる。

加工マクロのトラック名と `mml-repeat` の脱出対象は symbol または identifier に限る。不正な名前は `invalid mml-delay track name: 0 (expected a symbol)` のように、値・本文の評価や登録より前に位置付きのフォーム構文エラーで拒否する。名前を引用してシンボルとして扱うため、利用者マクロが生成した identifier も受け付ける。正しい型の未登録名は実行時の参照エラーとなり、先行トラックの登録は残る。

[[irの共有と最適化]]
=== IR の共有と最適化

整列化と最適化は入力 IR を変更しない。登録中の IR、出力用 IR、最適化結果の間でオブジェクトを共有する場合があり、インスタンスの同一性は保証しない。共有された IR を再編集する場合は、変更する範囲を複製して扱う。

具体的な IR クラスから派生させた IR にも、対応する既知の命令の最適化規則を適用する。再生成では原型のクラスと変更対象以外のインスタンススロットの値・未束縛状態を保持し、値自体は浅く共有する。削除・上書きされた IR や合成の原型に選ばれなかった IR の付加情報は保存しない。親の規則を適用できない独自の意味を持つ命令は、共通基底から定義する。

絶対指定の上書きは後続 IR、相対指定の合成は先行の寄与元、同一クラスのリズム設定のまとめ直しは最初の残存効果の寄与元、休符結合は後の休符を原型とする。LFO の選択と切替は別状態であり、派生 IR でも区別する。

[[fm音色の共通登録]]
=== OPN 系 FM 音色の共通登録

`define-opn-voice` と `sxmml-opn-voice-set!` は、使用・未使用にかかわらず全定義を登録時に検査する。OPM 音色・PCM 音色・波形の定義書式は xref:sxmml-reference-manual.adoc[MML 記述者向けリファレンス]を参照する。各項目は正確な整数に限り、範囲は次のとおりである。

[cols="1,1",options="header"]
|===
|項目 |受理範囲
|AL・FB |0～7
|AR・DR・SR |0～31
|RR・SL・ML |0～15
|TL |0～127
|KS |0～3
|DT |−3～7
|DT2 |0～3
|SEG |0～15
|AMS |0～1
|===

DT の −1・−2・−3 は 5・6・7 へ正規化し、既存の 0～7 は 4 も含め維持する。形の補完と全項目の検査が成功してから音色表を更新する。診断は `invalid voice @V1 operator(2) AR: 32 (expected an integer from 0 to 31)` のように音色名・演算子番号・項目名・指定値・必要な条件を示す。

pmd-source と pmd-binary は、利用者が直接組み立てた IR も受け付ける。どちらも、出力する FM 音色の 12 項目を個別に検査する。DT は正規化済みの 0～7 に限る。未使用の音色と、PMD に出力しない DT2・SEG はこの検査の対象外である。

[[トラック名とpartの対応]]
=== トラック名と part の対応

トラック名とバックエンドの part は独立した名前であり、管理用手続きが一対一対応を維持する。`define-track` と `sxmml-track-set!` は `:part` 省略時は未指定（`#f`）とし、明示した part は指定どおり使う。他のトラックが使用中の part への登録は値エラーとなる。同名再定義では自身を重複確認から除外し、新しい context に置き換える。以前の設定・MML・part は引き継がず、空いている別 part への再定義では旧 part を解放する。

`rename-track` と `sxmml-track-rename!` は同じ context を保持したまま登録名と context の `track` を変更し、旧名を除去する。part・設定・IR・コンパイル状態は保持する。変更元がなければ参照エラー、変更先が登録済みなら同名への変更も含め値エラーとする。マクロの名前は評価せず symbol または identifier を受け、手続きは symbol を受ける。形式や名前の型に違反するマクロはフォーム構文エラーとなる。取得できるフォーム位置は既知の実行時エラーにも添える。

検査に失敗した登録・名前変更手続きは、既存の登録・context・IR を変更しない。複数トラック形式の `:part` 指定は、登録前に `invalid define-track form: :part requires a single track` として拒否する。複数トラックは指定順に登録するため、後続の失敗によって先行する成功分を取り消さない。削除・全消去後は part を再利用できる。

コンテキストや登録表を直接編集して一対一対応を崩した場合、検索時の重複検査は行わず、候補選択と生成物の再現性は保証しない。

[[pmd-向け生成物]]
== PMD 向け生成物

PMD 向けの生成では、`-o`、ソースの既定値、入力ファイル名の拡張子を `.mml` に替えた名前の順に生成先を選ぶ。`filename` メタデータは生成先の指定に使わず、指定されていれば標準エラー出力に `warning: metadata 'filename' is ignored; use the -o option of sxlc to set the output file` を表示して無視する。

生成物は CP932 で書かれ、行末は CRLF である。先頭に元の入力ファイル名と `PMDver4.8` または `PMDver3.3` のモード行を含み、設定されたメタデータ、音色定義、データのあるトラックの行が続く。音色定義は、最適化レベルにかかわらず、生成する FM 音色指定から参照されるものだけを PMD の音色番号の順に出力する。実際の発音に寄与するかは追加解析しない。

FM パート A～F の固定順で、各パートの最適化後の音色指定に現れる異なる OPN 音色へ初出順に 0～255 を割り当てる。再参照には同じ番号を使う。定義数が 256 を超えていても、出力する音色指定が参照する種類数が 256 以下なら採番できる。257 種類目の参照は `too many voices: 257 (max 256)` で失敗する。

PMD が使うメタデータ（`title`・`composer`・`arranger`・`pcmfile`・`ppzfile`・`ppsfile`・`memo`）の値は、出力時に検査する。`memo` は文字列 1 つか文字列のリストを受け付ける。`pcmfile`・`ppzfile` は文字列または文字列リスト（各最大 1・2 件）、ほかのキーは文字列を受け付ける。型が違う場合は `invalid metadata value: title is 1 (expected a string)` のようにキーと値を表示して変換の失敗とする。

曲単位の設定 `detune`・`envelopespeed`・`lfospeed` はシンボル `normal`・`extend` を受け付け、明示した項目だけを `#Detune`・`#EnvelopeSpeed`・`#LFOSpeed` として出力する。PMD3 の MML（`-m pmd3`）は値をコメントとして書くが、同じく検査する。

LFO・エンベロープの定義は、`M`・`E` で使うときに検査する。種類は LFO が `default`・`triangle`（同じ意味）、エンベロープが `default` に限る。値の数は LFO が 4、エンベロープが 4・5・6 で、各値は範囲内の正確な整数に限る。

誤りは `unsupported LFO type: sw in L1 (supported: default, triangle)`、`invalid envelope values: E1 has 3 values (expected 4, 5 or 6)`、`invalid LFO L1 value 2: 300 (expected an integer from 0 to 255)` のように定義と誤りを表示して変換の失敗とする。種類・要素数・値の範囲の検査は、使わない定義と、最適化で取り除かれた命令の定義には行わない（登録時の外形検査とは区別する）。

同じ条件で変換した生成物はバイト単位で一致する（要求仕様の Q-03）。PMD3 形式は末尾に `0x1A` を付ける。日本語のタイトルも CP932 で出力する。

リズムの楽器別のパン（`p楽器 数値`）の値は、1 が右、2 が左、3 が中央で、それ以外は `invalid rhythm pan: 4 (expected an integer from 1 to 3)` のように値と範囲を表示して変換の失敗とする。PMD バイナリ生成物でも同じである。

PMD は固定パートに加えて、非空の PPZ8 トラックを名前順に最大 8 本採用する。PMD4 のソースとバイナリで割当と音色番号を共有する。PMD3 ではソースのみコメント付きの拡張宣言とパート本文を出力できる。

PMD と FMP7 は、明示した音源が未対応のトラックごとに標準エラー出力へ一度警告する。そのトラックをパート割り当て、上限判定、出力結果のトラック名から除く。PMD バイナリでは、空いた固定パートを空パートとして符号化する。

通常トラックとリズムの K 行では、最も多く登録された音長を既定音長に使う。PMD4 向けは tick 数を `l%N` として出力する。PMD3 向けは、全音符の tick 数（分解能の 4 倍）を既定音長の tick 数で割り、分母を `lN` として出力する。例えば分解能 24 で既定音長が 12 tick なら `l8` になる。割り切れない場合は、既定音長と分解能を示す値エラーになる。

モードごとの出力を比較するには、まず `mkdir -p /tmp/sxmml-examples/pmd-output` を実行し、`/tmp/sxmml-examples/pmd-output/modes.sxl` に `(mml G "c8")` を保存する。次のコマンドは同じ `modes.mml` を上書きするため、各回の出力を別名に保存する。

[cols="1,1,1,1",options="header"]
|===
|コマンド |`Processing Mode` |生成物のモード行 |末尾
|`sxlc -m pmd /tmp/sxmml-examples/pmd-output/modes.sxl` |`pmd-source` |`;; mode: PMDver4.8` |CRLF
|`sxlc -m pmd3 /tmp/sxmml-examples/pmd-output/modes.sxl` |`pmd3-source` |`;; mode: PMDver3.3` |`0x1A`
|===

`/tmp/sxmml-examples/pmd-output/source-mode.sxl` に `(sxmml-mode pmd3)` と `(mml G "c8")` を保存し、`sxlc -m pmd /tmp/sxmml-examples/pmd-output/source-mode.sxl` を実行すると、ソース中の指定は無視されて `Processing Mode: pmd-source` と表示され、生成物のモード行は
`;; mode: PMDver4.8` となる。`-m` を省くと、ソース中の指定により `Processing Mode: pmd3-source`、`;; mode: PMDver3.3` となる。

`-O` の水準によって生成行は変わる。例えば、`-O 0` の `G l%12v8v8o4crr`、`-O 1` の `G l%12v8o4crr`、`-O 2` の `G l%12v8o4cr%24` となる入力がある。通常の最適化を避けるには `-O 0` を指定する。品質上の制約は link:https://github.com/sayzbrdg/sxmml/issues/8[issue #8]を参照する。

空白を含む `space name.sxl` を変換して `-c "printf '%s\\n'"` を指定すると、生成先 `space name.mml` は一引数として渡る。`semi;name.sxl` の生成先 `semi;name.mml` も同様に一引数として渡る。`-w` の有無にかかわらず、`shell-tokenize-string` で分割するのは `COMMAND` だけであり、生成名は分割しない。

出力先の指定は、`/tmp/sxmml-examples/pmd-output/output-name.sxl` に以下を保存し、`sxlc -o /tmp/sxmml-examples/pmd-output/melody.mml -c 'printf %s' /tmp/sxmml-examples/pmd-output/output-name.sxl` で確認できる。`melody.mml` が生成され、`Translate` 行、`Post process` 行、後処理のいずれにもその生成先が使われる。`-o` を省くと `output-name.mml` が生成される。

[source,scheme]
----
(sxmml-mode pmd)
(mml G "c8")
----

[[pmd-source-の出力値の検査]]
=== pmd-source の出力値の検査

pmd-source が検査するのは、対応する命令と定義のうち link:https://github.com/d2lmirrors/pmd/blob/master/mc/PMDMML.MAN[PMDMML.MAN] に記載された制約である。生成した MML を受理するかどうかは MC.EXE が判定する。

FM・SSG・PCM の 3 区分で範囲が異なるものは分け、区分内の細かな音源・ドライバ差は最も広い範囲に合わせる。対象音源に記載がないことだけでは拒否せず、例えば SSG のパンもコマンド共通の 0～3 で検査する。値は正確な整数とする。

[cols="1,1",options="header"]
|===
|出力する指定 |許容範囲
|音量 |FM の `V`：0～127、SSG の `v`：0～15、PCM の `V`：0～255
|通常音符・ポルタメント両端の音程 |o1c～o8b。PCM 内の狭い範囲は検査しない
|ゲートタイム `q` |0～255
|デチューン `D` |−32768～32767
|転調 `++_++`・`++__++` |−128～127
|通常の相対音量 |増減量 −255～255
|パン `p` |0～3
|出力選択 `P` |1～3
|絶対ノイズ周波数 `w` |0～31
|直接指定の Timer-B 値 `T` |0～255。BPM 指定では換算後の値を検査する
|リズム全体の絶対音量 |0～63
|リズム楽器別の絶対音量 |0～31
|リズム楽器別の相対音量 |増減量 −31～31
|反復回数・最大同時入れ子数 |回数 1～255、深さ 32 段まで
|ポルタメントの音長 |1～255 clock
|===

通常音符・休符は一律 255 clock 以下に制限せず、長い音符・休符は分割して出力する。FM 音色定義は、出力する AL・FB・DT を 0～7、AR・DR・SR を 0～31、RR・SL・ML を 0～15、TL を 0～127、KS を 0～3、AMS を 0～1 で検査する。出力しない DT2・SEG、未使用の音色定義、最適化で削除された命令は追加検査しない。共通登録を迂回した音色も出力値を検査し、出力時の DT は正規化済みの 0～7 に限る。

範囲外の値や整数以外の値があれば、項目名・値・許容範囲を示して変換を終了する。pmd-binary の制約は <<pmd-バイナリ生成物>> を参照する。

[[pmd-バイナリ生成物]]
== PMD バイナリ生成物

`pmd-binary`・`pmd4-binary`・`pmd3-binary` は外部コンパイラを使わずに PMD のバイナリを直接生成する。生成物が MC.EXE の出力と同じであることは保証しない（PMD 向け MML を MC.EXE でコンパイルした結果と一致するとは限らない）。既知の欠陥は、ラベル `pmd-binary` の付いた link:https://github.com/sayzbrdg/sxmml/issues?q=is%3Aissue%20is%3Aopen%20label%3Apmd-binary%20label%3Abug[開いている不具合の issue]を参照する。

生成先は、`-o`、ソースの既定値、入力ファイル名の拡張子を `.m` に替えた名前の順に選ぶ。拡張子 `.m` の入力を `-o` もソースの既定値もなしで変換すると、出力先が入力ファイルと同じになるため使用法の誤り（終了値 2）となる。`filename` メタデータは PMD 向け生成物と同じく生成先の指定に使わず、警告を表示して無視する。

トラックの登録（A～F が FM、G～I が SSG、J が PCM、L がリズム）も PMD 向けのモードと同じである。生成物はバイナリであり、生成先と同じディレクトリの一時ファイルに書いてから生成先へ移す。

pmd-source・pmd-binary の両バックエンドで、音高の範囲外は内部の数値ではなく `invalid note: o9c (expected o1c - o8b)` のように音名で示す。ポルタメントでは `portamento start note` / `portamento end note` を区別する。BPM 由来の Timer-B の範囲違反は `invalid calculated Timer-B: 値 (from BPM 指定値; expected an integer from 下限 to 上限)` とし、計算結果であることと元の指定値を示す。換算処理の範囲は 0～255、pmd-binary の出力範囲は 0～250 である。

pmd-binary の相対音量は `invalid FM relative volume: -128 (expected an integer from -127 to 127)` のように符号付きの指定値と範囲を示す。FM は −127～127、SSG は −15～15、PCM は −255～255 とし、範囲外なら変換に失敗する。

`pmd-binary` と `pmd4-binary` は同じ PMD4 向けの生成物を作る。

曲単位の設定が `extend` のとき、デチューンは SSG、エンベロープ速度は SSG・PCM・PPZ8、LFO 速度は FM・SSG・PCM・PPZ8 に初期命令を書く。通常指定と省略時は初期命令を加えない。`pmd3-binary` でこれらのキーを明示すると、通常指定も含めて変換の失敗となる。PMD4 向けの生成物は、`title` などのメタデータの領域を含む。メタデータの値の検査は、PMD 向けの生成と同じである。

`pmd3-binary` の生成物はこの領域を含まず、LFO のチャンネル `B`（`invalid LFO channel: B`）と、5 値・6 値のエンベロープ（`unsupported envelope values in PMD3: E6 has 6 values (expected 4)`）は変換の失敗となる。LFO・エンベロープの種類と値の検査は、PMD 向けの生成と同じである。

PMD のどのモードでも、リズムの楽器別の音量（`v楽器 数値`）は 0 から 31 までで、範囲外は `invalid rhythm instrument volume: 32 (expected an integer from 0 to 31)` のように値と範囲を表示して変換の失敗とする。

PMD のどのモードでも、音高（ポルタメントの開始音・終了音を含む）は o1c から o8b までを表せる。範囲外の音高は、`invalid note: o9c (expected o1c - o8b)` のように範囲外の音高と許される範囲を表示して変換の失敗とする。

PMD のどのモードでも、255 tick を超える音符と休符は分割して書くが、ポルタメントの音長は分割できないため 255 tick までとし、超える場合は `invalid portamento ticks: 300 (expected an integer from 1 to 255)` のように音長と許される範囲を表示して変換の失敗とする。

生成物の大きさは 65535 バイトまでで、超える場合は `PMD data exceeds the size limit (65535 bytes) in track B` のように、超えた場所（トラック、`voice table`、`metadata`）を表示して変換の失敗とする。全体の大きさだけが超える場合は場所を表示しない。

PMD4 向けの生成物には、L トラックを含む全トラックの最大の合計 tick と、`L` のあるトラックの最大の loop tick（`L` のあるトラックがなければ 0）を書く。合計 tick は 65535 までで、超える場合は `total ticks exceed the limit: 67200 (max 65535)` のように、合計 tick と上限を表示して変換の失敗とする。使用した FM 音色だけを、PMD の音色番号の順に出力する。音色番号の振り方と上限は PMD 向けの生成と同じである。

失敗時の扱い（既存の生成物を変更せず、途中までの生成物を残さない。要求仕様の Q-02）と、同じ条件で変換した生成物がバイト単位で一致すること（要求仕様の Q-03）は、他のモードと同じである。

`/tmp/sxmml-examples/pmd-output/modes.sxl`（内容は `(mml G "c8")`）を各モードで変換すると、次のようになる。次のコマンドは同じ `modes.m` を上書きするため、各回の出力を別名に保存する。

[cols="1,1,1",options="header"]
|===
|コマンド |`Processing Mode` |生成物の大きさ
|`sxlc -m pmd-binary /tmp/sxmml-examples/pmd-output/modes.sxl` |`pmd-binary` |74 バイト
|`sxlc -m pmd4-binary /tmp/sxmml-examples/pmd-output/modes.sxl` |`pmd-binary` |74 バイト（`pmd-binary` と同じ内容）
|`sxlc -m pmd3-binary /tmp/sxmml-examples/pmd-output/modes.sxl` |`pmd3-binary` |40 バイト
|===

[[fmp7-向け生成物]]
== FMP7 向け生成物

`fmp7` は、CP932・CRLF の `.mwi` ファイルを生成する。対応音源を指定したトラックを採用し、音源種別の省略はエラーとする。トラック数は音源種別ごとに 32、合計 64 までとし、空トラックも数える。

明示パートを先に確保し、未指定分をトラック名順に空きへ対応付ける。パート名順に出力し、FM・PCM・エンベロープの各番号枠で初出順に採番する。出力先への反映は全トラックの変換成功後に行う。

[[nsdlib-向け生成物]]
== NSD.Lib 向け生成物

`nsdlib` は、一曲分の MML を UTF-8（BOM なし）の `.nsd` ファイルに出力する。空トラックは割り当てから除く。休符だけのトラックは出力対象になる。

同じ音源を使うトラックは名前の辞書順に割り当て、TR 番号順に出力する。使用音源に応じて標準・FDS・VRC6 のドライバーを選ぶ。FDS と VRC6 を同じ曲で使うことはできない。

[[失敗条件と境界値]]
== 失敗条件と境界値

`sxlc` の終了値は次のとおりである（link:https://github.com/sayzbrdg/sxmml/issues/37[issue #37]）。ソース中の Scheme 式が `exit` を呼んだ場合は、その値で終了する。

[cols="1,1",options="header"]
|===
|終了値 |意味
|0 |成功。`-c` を指定した場合は後処理も成功
|1 |変換の失敗。既知の入力エラーは `++sxlc: error: [ファイル:行: ]本文[ on トラック track]++` の形で標準エラー出力へ表示する。位置とトラックは取得できる文脈だけを使い、Gauche の例外見出しやスタックトレースを付けない。未知の Gauche エラー、I/O、内部 IR・最適化の整合性検査の失敗は、Gauche の標準報告とスタックトレースを維持する
|2 |使用法の誤り。不正なオプションや引数、入力ファイル名なし、`-m` に未登録のモード名を指定、`-c` の字句の誤り、出力先が入力ファイルと同じ、入力ファイル名より後ろの引数。誤りの内容を標準エラー出力に、使用法を標準出力に表示する
|3 |後処理の失敗。`-c` の後処理が 0 以外の終了値やシグナルで終了した、起動できなかった、`-w` の `wslpath` が失敗した
|===

表中の Scheme 入力を試す場合は、それぞれ 1 行の `/tmp/sxmml-examples/invalid-input.sxl` に保存し、特記した条件以外は `sxlc -m pmd /tmp/sxmml-examples/invalid-input.sxl` を実行する。「モードを指定しない空ソース」は空ファイル、「未登録トラック」は `(mml G "c8r8")` だけを記したファイルを `-m` なしで読み込む。「入力ファイル名なし」は `sxlc` を実行する。

既知の入力エラーの結果欄は本文を示す。CLI は共通の見出しと取得済みの位置・トラックを付ける。例えば上記の入力ファイルの 1 行目の通常 MML で未知の文字を指定した場合、`sxlc: error: /tmp/sxmml-examples/invalid-input.sxl:1: unknown MML command: "x" on G track` のように取得できるフォーム位置を添える。

[cols="1,1",options="header"]
|===
|条件と入力 |結果
|入力ファイル名なし |`no source file specified` と使用法を表示し、終了値 2
|`/tmp/sxmml-examples/invalid-input.sxl` を `-o /tmp/sxmml-examples/invalid-input.sxl` を付けて変換 |`output file is the same as the source file: /tmp/sxmml-examples/invalid-input.sxl` と使用法を表示し、終了値 2。ソースは変更しない
|`(mml G "c8")` を `/tmp/sxmml-examples/same.mml` に保存して `-o` なしで変換 |既定の出力先が入力と同じになるため `output file is the same as the source file: /tmp/sxmml-examples/same.mml` と使用法を表示し、終了値 2。ソースは変更しない
|`sxlc -m pmd /tmp/sxmml-examples/invalid-input.sxl -o /tmp/sxmml-examples/out.mml` のように入力ファイル名の後ろにオプションを書く |`unexpected argument after the source file: -o`、`options must be placed before the source file` と使用法を表示し、終了値 2。生成物は作らない
|`-m nosuch` で存在しないモードを指定 |`undefined mode: nosuch` と使用法を表示し、終了値 2
|モードを指定しない空ソース |`backend is not specified by option or source file`、終了値 1
|未登録トラックへ `(mml G "c8r8")` を評価 |`undefined track: G`、終了値 1。モード未指定の判定より先に失敗
|`(sxmml-resolution 0)` |`invalid resolution: 0 (expected a positive integer)`、終了値 1
|`(mml G "c0")` |`invalid note length: 0 (expected an integer >= 1)`、終了値 1
|`(rhythm L "@b0")` |`invalid note length: 0 (expected an integer >= 1)`、終了値 1
|`(mml G "c8x")` |`unknown MML command: "x"`、終了値 1
|`(rhythm L "@b8x")` |`unknown MML command: "x"`、終了値 1
|`(rhythm L "@x8")` |`invalid MML syntax near "x8"` とトラック情報、終了値 1
|`++(mml G "[ab]0")++`・`++(mml G "[a:b]0")++`・`++(rhythm L "[@b8:@s8]0")++` のように反復回数 0 を書く |`invalid repeat count:` と指定値、終了値 1。波括弧付き・ゼロ埋めの 0 も同じ
|`(mml G "]1")` のように開始命令のない反復終端を書く |`repeat end appeared before repeat start`、終了値 1
|`(mml G "c8Ld8Le8")` や `(rhythm L "@b8L@s8L@h8")` のように同じトラックに `L` を複数書く |`loop command can be used only once in a track`、終了値 1。複数回の登録にまたがる 2 個目も同じ
|`++(mml G "c8[d8 L e8]2")++` や `++(rhythm L "@b8[@s8 L @b8]2")++` のように反復の中に `L` を書く |`loop command cannot be used inside repeats`、終了値 1。入れ子の内側、`:` の後ろ、`mml-repeat` の本文、複数の `mml` にまたがる反復の中も同じ
|`(mml A "@0c8")` で未定義の FM 音色 `@0` を使う |生成中に `undefined voice`、終了値 1
|通常トラック G で `(mml G "c%0")` |`invalid tick length: 0 (expected a positive exact integer)`、終了値 1。新規出力なし
|`(rhythm L "@b%0")` |`invalid tick length: 0 (expected a positive exact integer)`、終了値 1。新規出力なし
|`(rhythm L "r%0")` |`invalid tick length: 0 (expected a positive exact integer)`、終了値 1。新規出力なし
|`(mml G "c8")` を `-o /tmp/sxmml-examples/no-such-dir/out.mml` を付けて変換 |`mkstemp failed: No such file or directory`、終了値 1
|`(mml G "c8")` を `-o /tmp/sxmml-examples` を付けて変換（出力先が既存のディレクトリ） |一時ファイルを出力先へ改名できず `renaming` で始まるエラー、終了値 1
|`(mml G "c8")` を `-c false` を付けて変換 |生成後に `post process failed: exit status 1`、終了値 3。生成物は残る
|===

値が 0 の tick 指定は、先頭に 0 を追加しても同じエラーになる。`8&%00` など加算する部分が 0 の入力も拒否する。一方、`c%01` と `c%00012` はそれぞれ 1 tick と 12 tick で成功する。失敗の種類によっては、生成を開始した後でエラーになる。`@0` の例では生成中にエラーとなり、`Translate` 行は表示されない。

上表の失敗のうち終了値 1 と 2 のものはいずれも、ソースの読み込み、生成、出力先への書き込みのどこで起きても、出力先の既存ファイルを変更せず、途中までの生成物や一時ファイルを残さない（要求仕様の Q-02）。生成物は出力先と同じディレクトリの一時ファイルに書き、書き終えてから出力先へ改名する。変換に失敗した場合は、出力先に残っているファイルは以前の変換の生成物であるため、後処理へ渡さず、原因を修正して再実行する。

[[使用例]]
== 使用例

次の内容を `/tmp/sxmml-examples/melody-and-rhythm.sxl` に保存する。`/tmp/sxmml-examples` は事前に作成する。

[source,scheme]
----
(sxmml-mode pmd)
(define phrase (list "c8" "r8"))
(mml G phrase)
(rhythm L "@b8r8")
----

[source,console]
----
sxlc /tmp/sxmml-examples/melody-and-rhythm.sxl
# => Processing Mode: pmd-source
# => Optimize level: 1
# => Track G: total: 24
# => Track L: total: 24
----

生成先は `/tmp/sxmml-examples/melody-and-rhythm.mml`。この例では `G l%12o4cr` を含む PMD 向けファイルができる。入力のコードは Gauche によって評価されるため、実行環境の権限で動作する。

日本語タイトルの例として、`/tmp/sxmml-examples/japanese-title.sxl` に `(define-metadata title "曲")` と `(mml G "c8")` を保存し、`sxlc -m pmd /tmp/sxmml-examples/japanese-title.sxl` を実行する。生成ファイル `japanese-title.mml` は CP932 として復号でき、`#title       曲` を含む。
