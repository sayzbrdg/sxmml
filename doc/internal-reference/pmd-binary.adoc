= `sxmml.backend.pmd-binary` の生成処理
:toc: left

外部コンパイラ（MC.EXE）を介さずに PMD のバイナリ（`.m`）を直接生成するバックエンドです。生成物が MC.EXE の出力と同じであることは保証しません（xref:pmd-source.adoc[`sxmml.backend.pmd-source`] の出力を MC.EXE でコンパイルした結果と一致するとは限りません）。

このモジュールは、PMD 4.8s のソースで命令コードの対応を確認し、MC.EXE の生成物の差分から形式を解析した独自実装です。解析の経緯と謝辞は link:../../README.md#謝辞[README の謝辞]を参照してください。既知の欠陥は、ラベル `pmd-binary` の付いた link:https://github.com/sayzbrdg/sxmml/issues?q=is%3Aissue%20is%3Aopen%20label%3Apmd-binary%20label%3Abug[開いている不具合の issue] を参照してください。

読み込み時にモード `pmd-binary`（別名 `pmd4-binary`）と `pmd3-binary` を登録し、モード選択時に `sxmml-pmd-setup!` で初期トラックを登録します。出力手続きは出力環境一つを受け取り、出力先と採用トラック名を持つ `<sxmml-output-result>` を返します。出力中に現在の登録環境・選択モード・`sxmml-source-file` を参照せず、入力環境と IR は変更しません。

出力先が `#f` の場合は `<sxmml-value-error>`（`output file is not specified`）になります。一時ファイルへ書き出してから出力先へリネームするため、途中で失敗しても既存の出力ファイルは変更しません。

エラーの分類は次のとおりです。

* 数値・定義形式・チャンネル・PMD3 非対応機能の違反: `<sxmml-value-error>`
* 未定義の音色・LFO・エンベロープ: `<sxmml-reference-error>`
* 同一トラック内の重複 `L`: `<sxmml-mml-syntax-error>`
* 生成物サイズ（65535 バイト）および最大合計 tick（65535）の上限超過、FM 音色の 257 種類目参照: `<sxmml-error>`
* I/O や Gauche の内部エラー: そのまま送出

実装は link:../../sxmml/backend/pmd-binary.scm[pmd-binary.scm] にあります。このページでは公開名 4 件（3 手続きと 1 クラス）を個別に記載し、`%` で始まる内部手続きは群ごとの概要とバイナリ配置に留めます。

== 公開名

[[ref-pmd-binary-class-sxmml-pmd-binary-environment]]
=== `<sxmml-pmd-binary-environment>`

バイナリ生成中の作業バッファとメタ情報を保持するクラスです。`(make <sxmml-pmd-binary-environment> :offset 値 :environment 出力環境 :fm-voices 採番状態 [:mode 値] [:head-length 値] [:track ベクタ] [:track-length ベクタ])` で生成します。

* `offset`（`:offset`）: 先頭 `0x00` の直後を 0 とした現在の書き込み位置。
* `mode`（`:mode`、初期値 `#f`）: PMD3 向けは `'fc88`、PMD4 向けは `#f`。
* `head`（初期値 26 バイトの `u8vector`）・`head-length`（`:head-length`、初期値 `26`）: ヘッダ領域とその長さ。
* `track`（`:track`、既定は 13 要素のベクタ）・`track-length`（`:track-length`、既定は 13 要素の 0 埋めベクタ）: A～J・K・R・音色表／メタ情報の基本 13 領域に、使用中の PPZ8 パート数を加えたバッファ群とその長さ。`initialize` メソッドが各要素へ 65600 バイトの `u8vector` を確保します。
* `max-total-ticks`・`max-loop-ticks`（各初期値 `0`）: 採用トラック全体での最大の合計 tick とループ tick。
* `fm-voices`（`:fm-voices`）: 使用 FM 音色の採番状態（`<sxmml-pmd-fm-voices>`）。
* `environment`（`:environment`）: 読み取り用の `<sxmml-output-environment>`。

[[ref-pmd-binary-sxmml-pmd-binary-output]]
=== `(sxmml-pmd-binary-output env)`

出力環境 `env` から PMD4 向けのバイナリ（`.m`）を生成し、`<sxmml-output-result>` を返します。`env` の `output` が `#f` の場合は `<sxmml-value-error>`（`output file is not specified`）になります。

[[ref-pmd-binary-sxmml-pmd4-binary-output]]
=== `(sxmml-pmd4-binary-output env)`

`sxmml-pmd-binary-output` と同じ PMD4 向けの公開出力手続きです。

[[ref-pmd-binary-sxmml-pmd3-binary-output]]
=== `(sxmml-pmd3-binary-output env)`

出力環境 `env` から PMD3 向け（`mode` を `'fc88`）のバイナリを生成し、`<sxmml-output-result>` を返します。拡張設定（`detune`・`envelopespeed`・`lfospeed`）の明示、PPZ8 トラックの使用、LFO チャンネル `B`、3 値の `evolution` LFO、5 値・6 値エンベロープは `<sxmml-value-error>` になります。

== 内部手続きの群

共通の生成本体 `%sxmml-pmdx-binary-output` は、出力環境から `sxmml-pmd-output-tracks-select`（`backend` 引数は `'pmd-binary`）で A～J・L と非空の PPZ8 トラックを選び、`sxmml-pmd-for-each-track-ir` で最適化しながら順に符号化します。作業環境 `<sxmml-pmd-binary-environment>` は呼び出しごとに生成して各内部手続きへ明示的に渡します。

トラック走査と命令出力の責務は、次の 6 つの群に分かれています。

トラック変換::
`%fm-track-u8vector-set!`・`%ssg-track-u8vector-set!`・`%pcm-track-u8vector-set!` が音源別の音色・音量・相対音量手続きを選んで `%pmd-track-u8vector-set!` へ渡します。
+
`%pmd-track-u8vector-set!` は非公開の `<sxmml-pmd-binary-track-environment>` を作り、サイズ検査を行いながら各 IR を `%pmd-ir-u8vector-set!` で書き込み、ループ検出状態と反復スタックを再帰引数で引き継ぎます。同一トラック内の 2 個目の `L` は `<sxmml-mml-syntax-error>` です。末尾に終端 `0x80` を書き、固定パート（`hoffset` 指定時）はヘッダの次トラック位置を更新します。
+
反復終了命令（`0xf8`）の 2 バイト目には回数（255 以下）、3 バイト目には脱出があれば `回数 - 1`、脱出がなければ `回数` を書きます。反復回数はコンパイラが保証する正の正確な整数を前提とします。

命令の書き込み::
`%pmd-...-set!` が `u8vec` の `offset` から 1 命令を書き込み、次の書き込み位置を返します。1 バイト・2 バイト引数の範囲は `%pmd-1byte-set!`・`%pmd-2bytes-set!`（引数 `(u8vec offset cmd value max min kind)`）で検査し、範囲外は項目名・指定値・許容範囲を示す `<sxmml-value-error>` にします。
+
相対音量は `%pmd-volume-change-value` で符号付きの値と範囲（FM −127～127、SSG −15～15、PCM −255～255）を検査してから符号化します。BPM 由来の Timer-B は `env` の分解能で換算した結果を 0～250 で検査し、超過時は計算結果と元の BPM を示します。
+
255 tick を超える音符はタイ（`0xfb`）で、休符は休符の連続で分割します。ポルタメント（`0xda`）は音長を 1 バイトで持つため分割せず、1～255 tick の範囲外は `invalid portamento ticks: 値 (expected an integer from 1 to 255)` の `<sxmml-value-error>` になります。
+
`%pmd-lfo-set!` は `<sxmml-mml-lfo>` と `<sxmml-pmd-lfo-evolution>` を受け付けます。`evolution` はチャンネル `#f`・`A` で `0xd6`、チャンネル `B` で `0xbd` に続けて値 1 と値 2（符号付き 1 バイト）を書き（1 値定義は値 2 を `0`）、3 値のときはさらに `0xb7` と値 3（チャンネル `B` は bit7 を立てた `0x80 | 値 3`）を書きます。値 1 が `0` の 3 値および PMD3 での 3 値は `<sxmml-value-error>` になります。

リズム::
L トラックの IR を K トラック（`%pmd-rhythm-deploy-track-u8vector-set!`）と R トラック（`%pmd-rhythm-definition-track-u8vector-set!`）へ出力します。R トラックでは局所手続きが 1 命令ずつ書き込み、`L` によるパターン区切りと重複 `L` 検査、末尾の終端 `0xff` と PMD4 向け 12 バイト領域を確定します。
+
楽器別の音量（0～31）とパン（1～3）は `楽器番号 × 32 + 値` の 1 バイトに符号化するため、`%pmd-rhythm-volume-set!`・`%pmd-rhythm-pan-set!` が符号化前に範囲を検査します。

メタ情報・音色表::
`%pmd-meta-track-u8vector-set!` が使用 FM 音色表と PMD4 向けメタ情報を出力します。音色表への書き込み直前に `%opn-voice-form\->register-data` が使用音色の 12 項目（AL・FB・DT=0～7、AR・DR・SR=0～31、RR・SL・ML=0～15、TL=0～127、KS=0～3、AMS=0～1）を検査して OPN レジスタ列へ変換します（DT の負数正規化は共通登録側で行い、出力時の負の DT は拒否します。DT2・SEG と未使用音色は検査しません）。
+
PMD4 では続けて CP932 の NUL 終端文字列群と位置表を書き込み、R トラック末尾のメタ情報位置表ポインタを確定します。PCM 音色の番号解決は xref:pmd.adoc[`sxmml-pmd-pcm-voice-number`] を使います。

出力::
`%pmd-binary-output` が `sxmml-pmd-check-obsolete-metadata` で `filename` 警告を確認した後、先頭 `0x00`、ヘッダ、各トラック領域を一時ファイルへ書いて出力先へリネームします。

補助::
`%short\->le-bytes` は 16 ビット整数をリトルエンディアン 2 バイトに分けます。`%note-number\->pmd-note` は音高を PMD の 1 バイト表現へ変換し、`o1c`～`o8b` の範囲外は `%note-number\->name` の音名表記で `<sxmml-value-error>` を送出します。
+
`%size-check` は先頭 `0x00` を除くデータ長が 65534 バイト（総サイズ 65535 バイト）を超えないか検査し、超過時はパラメータ `%pmd-section` が示す場所を添えて `<sxmml-error>` を送出します。`%shift-jis-u8vector-copy!` は文字列を CP932 の NUL 終端バイト列として書き込みます。`%ticks-update!` は採用トラックから最大の合計 tick と loop tick を更新します。

== バイナリの配置

位置は、先頭の `0x00` の次のバイトを 0 としたオフセットです。

. 先頭の 1 バイトは `0x00` です。
. 続く 26 バイトがヘッダです。リトルエンディアン 2 バイトずつ 13 個の位置を持ち、A～F・G～I・J・K・R の各トラック先頭と音色表の先頭を指します。
. 各トラックの命令列が続きます。A～J の各トラックは `0x80` で終わります。
. K トラックは、L が空なら `0x80` だけです。L にループがあれば `0x00 0xf6 0x01 0x80`、なければ `0x00 0x80` になります。
. PPZ8 使用時（PMD4 のみ）は、J の先頭に `0xb4` と 8 件のリトルエンディアン 16 ビット参照欄（計 17 バイト）を置きます。使用中の PPZ8 パート本文は K の後ろに順に並び、各末尾は `0x80` です。未使用の参照欄は 0 です。PMD3（`fc88`）で PPZ8 トラックがある場合は `PPZ8 tracks are unsupported in PMD3` の `<sxmml-value-error>` になります。
. PMD4 の拡張設定は各パート本文の先頭（J では PPZ8 参照欄の後ろ）に置きます。空の固定パートにも出力します。命令の順序は SSG のデチューン（`0xcc 0x01`）、SSG・J・PPZ8 のエンベロープ速度（`0xc9 0x01`）、FM・SSG・J・PPZ8 の LFO 速度（`0xca 0x01 0xbb 0x01`）です。省略と `normal` は命令を追加しません。PMD3 ではこれら 3 キーの明示を `<sxmml-value-error>` にします。
. R トラックは、パターン位置表（ループなしは 2 バイト、ループありは 4 バイト）に続いてリズム命令列を置き、`0xff` で終わります。L が空のときはパターン位置表も命令列も置きません。PMD4 向けでは続けて 12 バイトの領域に、2 バイトずつ最大合計 tick（65535 超は `<sxmml-error>`）、`0`、最大 loop tick（`L` がなければ `0`）、`0`、メタ情報位置表へのポインタ、固定値 `0x48 0xfe` を置きます。
. 音色表は、FM パート A～F で参照された音色の初出順に、音色番号 1 バイトと音色データ 25 バイトを並べます。PMD4 向けは末尾に `0x00 0xff` を置き、PMD3 向けは終端を置きません。
. PMD4 向けでは、最後にメタ情報を置きます。`ppzfile`・`ppsfile`・`pcmfile`・`title`・`composer`・`arranger`・`memo`（0 件以上）の順に CP932 の NUL 終端文字列を並べ、各文字列への開始位置表を `0x00 0x00` で終えます。`memo` 以外の未定義項目は空文字列（`0x00` のみ）を書き、`memo` は要素の数だけ書きます（未定義または空リストのときは書き込みも位置表エントリも置きません）。

PMD3 向け（`fc88`）では、メタ情報と R トラック末尾の 12 バイトを置かず、LFO のチャンネル `B`（`invalid LFO channel`）、3 値の `evolution` LFO（`unsupported evolution LFO values in PMD3`）、5 値・6 値のエンベロープ（`unsupported envelope values in PMD3`）を `<sxmml-value-error>` にします。

== PMD4 と PMD3 の違い（MC.EXE の生成物から）

MC.EXE 4.8s で、同じ MML を PMD4 向けと PMD3 向けにコンパイルした生成物を比較して確認した差異です。`pmd-binary` は MC.EXE と同じ生成物を作ることを保証しないため、以下の差異は不具合として扱いません。

反復終了命令（`0xf8`）の 3 バイト目は、脱出のない 1 回の反復で異なります。`pmd-binary` は PMD3 向けでも PMD4 向けと同じ値を書きます。

[cols="1,1,1,1",options="header"]
|===
|MML |PMD4 向けの MC.EXE |PMD3 向けの MC.EXE |`pmd-binary`
|`[c:d]1` |0 |0 |0
|`[cd]1` |1 |0 |1
|===

PMD3 向けで 2 回以上の反復の値は確認していません。また、PMD3 向けの MC.EXE の生成物は `#memo` を 0～3 件書いた MML でも同一であり、PMD3 向けの `pmd-binary` がメタ情報を置かない仕様と一致しています。
