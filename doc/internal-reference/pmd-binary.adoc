= `sxmml.backend.pmd-binary` の生成処理（実験的）
:toc: left

既存の数値・定義形式の検査はvalue-error、未定義の音色・LFO・エンベロープはreference-error、重複Lはmml-syntax-errorです。生成物サイズとトラック長の上限は基底sxmml-errorで通知します。I/Oや内部のGaucheエラーは包み直しません。

`sxmml.backend.pmd-binary` は、外部コンパイラ（MC.EXE）を介さずに PMD のバイナリ（`.m`）を直接生成する実験的なバックエンドです。生成物が MC.EXE の出力と同じであることは保証しません（`sxmml.backend.pmd` の出力を MC.EXE でコンパイルした結果と一致するとは限りません）。正式機能とするかどうかは https://github.com/sayzbrdg/sxmml/issues/54[issue #54] で判断します。

このモジュールは、PMD 4.8s のソースで命令コードの対応を確認し、MC.EXE の生成物の差分から形式を解析した独自実装です。処理の移植・翻訳はしていません。解析の経緯と謝辞は link:../../README.md#謝辞[README の謝辞]を参照してください。

実験的な機能であるため、このページでは公開名 7 件だけを項目として記載します。`%` で始まる内部手続きは、群ごとの概要とバイナリの配置の概要に留めます。既知の欠陥は、ラベル `pmd-binary` の付いた link:https://github.com/sayzbrdg/sxmml/issues?q=is%3Aissue%20is%3Aopen%20label%3Apmd-binary%20label%3Abug[開いている不具合の issue] を参照してください。パラメータ、オブジェクト、文字コード変換、一時ファイル、ファイル名操作は Gauche 0.9.15 の動作に従います。

共通の生成処理は、A～F、G～I、J、L のトラックを `sxmml-track-find` で探します。登録されていないトラックがあると失敗します。生成手続きはモード手続きを呼ばずに使えますが、その場合はこれらのトラックを `define-track` で登録しておく必要があります。出力先は環境の `output` slot です。この slot が `#f` のときは、`sxmml-source-file` の拡張子を `.m` に替えたパスを使い、それもなければ `./a.m` を使います。使ったパスは `output` slot に設定します。`filename` メタデータが指定されていれば警告を表示し、生成先には使いません。生成物は出力先と同じディレクトリの一時ファイルに書いてから出力先へ改名するので、途中で失敗しても出力先の既存のファイルは変更しません。未定義の FM 音色・LFO・エンベロープの参照や、範囲外の値は失敗します。

== 内部手続きの群

通常トラックの `%pmd-track-u8vector-set!` と、リズム定義の `%pmd-rhythm-definition-track-u8vector-set!` は、既存のIR出力走査中にループ開始を処理済みかを保持します。2個目は区切りやポインタをバッファへ書く前に `loop command can be used only once in a track` エラーとします。状態はトラックごとに独立し、解析コンテキストの `loop-exists` に依存せず、直接渡されたIRも検査します。

[cols="2,5",options="header"]
|===
|群 |概要
|トラック変換 |`%fm-track-u8vector-set!`・`%ssg-track-u8vector-set!`・`%pcm-track-u8vector-set!` は、音色・音量・音量変化の書き込み手続きを音源の種類ごとに選び、`%pmd-track-u8vector-set!` に渡します。`%pmd-track-u8vector-set!` はオブジェクト型ごとに書き込み手続きを呼び、終端の `0x80` を書いてヘッダの次のトラックの位置を更新します。反復の開始・脱出の位置は、手続き内のスタックで解決します。反復回数はコンパイラが保証する正の正確な整数を前提とします。反復の終了の命令（`0xf8`）の 2 バイト目には回数を、3 バイト目には、脱出のある反復では回数 - 1、脱出のない反復では回数を書きます
|命令の書き込み |`%pmd-...-set!` は `u8vec` の `offset` から 1 命令を書き、次の書き込み位置を返します。値の範囲は、`%pmd-1byte-set!`・`%pmd-2bytes-set!` で検査します。255 tick を超える音符はタイ（`0xfb`）で、休符は休符の連続で分割します。ポルタメント（`0xda`）は音長を 1 バイトで持ち、分割できないので、`%pmd-portamento-set!` が 1〜255 tick に限り、超えると `portamento ticks out of range: 300 (1 - 255)` で失敗します
|リズム |`%pmd-rhythm-track-u8vector-set!` は、K トラック（`%pmd-rhythm-deploy-track-u8vector-set!`）と R トラック（`%pmd-rhythm-definition-track-u8vector-set!`）に L の内容を分けて書きます。`%pmd-rhythm-emit-set!` などがリズム音源の命令を書きます。楽器別の音量とパンは、楽器 * 32 + 値の 1 バイトに符号化するので、`%pmd-rhythm-volume-set!`・`%pmd-rhythm-pan-set!` が符号化の前に値（音量は 0～31、パンは 1～3）を検査し、範囲外は書いた値と範囲を示して失敗します
|メタ情報・音色表 |`%pmd-meta-track-u8vector-set!` は、使用した FM 音色を音色番号（`voice-numbers` の値）の順に並べた音色表と、PMD4 向けのメタ情報を書きます。`%opn-voice-form\->register-data` は音色定義を OPN のレジスタ値の並びに変換します
|出力 |`%pmd-binary-output` は、先頭の `0x00`、ヘッダ、各トラックを一時ファイルに書き、出力先へ改名します。`%output-file-get` は出力先を決め、`%check-obsolete-metadata` は `filename` メタデータの警告を表示します

== バイナリの配置

以下は、コードから読み取れる範囲での配置の概要です。位置は、先頭の `0x00` の次のバイトを 0 とした値です。

. 先頭の 1 バイトは `0x00` です。
. 続く 26 バイトがヘッダです。2 バイトずつ 13 個の位置を持ち、A～F、G～I、J、K、R の各トラックの先頭と、音色表の先頭を指します。
. 各トラックの命令列が続きます。A～J の各トラックは `0x80` で終わります。
. K トラックは、L が空なら `0x80` だけです。L にループがあれば `0x00 0xf6 0x01 0x80`、なければ `0x00 0x80` になります。
. R トラックは、パターンの位置（ループがあればループ位置も）に続いてリズムの命令列を置き、`0xff` で終わります。L トラックが空のときは、パターンを作らず、位置も命令列も置きません。PMD4 向けでは、続く 12 バイトに、2 バイトずつ、L トラックを含む全トラックについての最大の合計 tick、`0`、`L` のあるトラックについての最大の loop tick（`L` のあるトラックがなければ 0）、`0`、メタ情報の位置の表へのポインタ、固定値 `0x48 0xfe` を置きます。
. 音色表は、使用した FM 音色ごとに、音色番号 1 バイトと音色データ 25 バイトを並べます。PMD4 向けでは `0x00 0xff` で終わり、PMD3 向けでは終端を置きません。
. PMD4 向けでは、最後にメタ情報を置きます。`ppzfile`・`ppsfile`・`pcmfile`・`title`・`composer`・`arranger`・`memo`（0 件以上）の順に、CP932 の NUL 終端文字列を並べ、それぞれへの位置の表を `0x00 0x00` で終えます。値は `sxmml.backend.pmd` の `sxmml-pmd-metadata-value` で、`-m pmd` と同じ規則で検査します。`memo` 以外の定義のない項目は、空文字列になります。`memo` は要素の数だけ書き、定義がないときと空のリストのときは書きません（位置の表にも項目を置きません）。

PMD3 向け（`fc88`）では、メタ情報と R トラックの 12 バイトを置かず、LFO のチャンネル `B`（`invalid lfo channel`）と 5 値・6 値のエンベロープ（`unsupported envelope values in PMD3`）を失敗とします。LFO・エンベロープの種類と値は、`sxmml.backend.pmd` の `sxmml-pmd-lfo-values`・`sxmml-pmd-envelope-values` で、`-m pmd` と同じ規則で検査します。

== PMD4 と PMD3 の違い（MC.EXE の生成物から）

MC.EXE 4.8s で、同じ MML を PMD4 向けと PMD3 向けにコンパイルした生成物を比べて分かった違いです。pmd-binary は MC.EXE と同じ生成物を作ることを保証しないので、ここに記す違いは不具合として扱いません。

反復の終了の命令（`0xf8`）の 3 バイト目は、脱出のない 1 回の反復で違います。pmd-binary は、PMD3 向けでも PMD4 向けと同じ値を書きます。

[cols="1,1,1,1",options="header"]
|===
|MML |PMD4 向けの MC.EXE |PMD3 向けの MC.EXE |pmd-binary
|`[c:d]1` |0 |0 |0
|`[cd]1` |1 |0 |1
|===

PMD3 向けで、2 回以上の反復の値は確かめていません。

PMD3 向けの MC.EXE の生成物は、`#memo` を 0～3 件書いた MML でも同じでした。PMD3 向けの pmd-binary がメタ情報を置かないことと合っています。
