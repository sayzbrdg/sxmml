= `sxmml.processor` の MML 加工
:toc: left

既存の加工値と先行音なしはvalue-error、マクロの形式違反はform-syntax-error、未定義トラックはreference-errorです。取得できるマクロ位置は既知のエラーへだけ合成します。値の式の未定義変数はGaucheの例外をそのまま通します。

`sxmml.processor` は三つのマクロを公開し、二つの加工手続きと五つの補助手続きを内部で使います。トラックは事前に `define-track` 等で登録してください。本文の Scheme 式は、展開された登録式の実行時に評価されます。マクロ展開と `util.match` は Gauche 0.9.15 の動作に従います。MML 記述者向けの例は xref:../sxmml-reference-manual.adoc[公開機能リファレンス]を参照してください。

加工手続きはsxmml IR の列 `ir` を受け、新たな音符・音量変更オブジェクトを挿入した列を返します。音符や休符の `ticks` slot を変更する場合がありますが、コンテキストの `current-ticks` を再計算しません。戻り値を `sxmml-ir-register!` で登録するのはマクロ側です。

マクロは xref:form.adoc[`sxmml.form`] を使い、`define-opn-voice` などの定義のマクロと同じ形にしています。書式（括弧の数と形）は展開時に検査し、誤りは `sxmml-form-error` で位置を付けて投げます。回数や値は式として評価し、加工手続きと `%mml-repeat-end-format` が実行時に検査します。登録の呼び出しは `sxmml-form-wrap` で包むので、既知の値・参照の誤りにだけ、マクロの開始位置を独立したconditionとして添えます。値の式の未定義変数はそのまま通します。ただし `mml-repeat` の本文は `begin` に直接並べるので、包みません。本文の中のエラーは、そのフォーム自身の扱いに従います。

`mml-repeat` の二本文形は `(mml-repeat track times (body1 ...) (body2 ...))` で、`body1` の後に脱出位置を置きます。三本文形は単一トラックなら `(mml-repeat track times (body1 ...) (body2 ...) (body3 ...))`、複数トラックなら第三本文の先頭に脱出対象を置く `(mml-repeat (track ...) times (body1 ...) (body2 ...) ((break ...) body3 ...))` または `(break body3 ...)` です。三本文形では `body3` が反復終了後に置かれます。

`mml-delay` は音符の後に続く休符を処理します。`mml-echo` は単一トラック形だけを受け、複数トラック形は使用できません。`mml-repeat` の三本文形は、`body1` と `body2` の間に脱出位置を置き、`body3` を反復後に実行します。複数トラック形では指定したトラックだけに脱出位置を置きます。第三節の本文を省略しても構いません。xref:../sxmml-reference-manual.adoc#mml-repeat[第三節の用途と入力例]を参照してください。

== ディレイの例

次のコマンドは Gauche 0.9.15 で加工後のオブジェクト数を確認します。`mml-delay` では音符に続く 12 tick の休符が加工対象です。

[source,console]
----
$ gosh -I. -e '(use sxmml)' -e '(define-track G)' -e '(mml-delay G (6 2 1) "c8r8")' -e '(print (length (sxmml-optimize-tree (quote G) :optimize #f)))'
6
----
