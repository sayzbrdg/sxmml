= `sxmml.compiler` のコンパイル処理
:toc: left

PEGドライバのparse-errorはcompilerの境界でmml-syntax-errorへ変換し、元のPEG conditionは保持しません。明示的な理由とnear表記は維持します。既知のエラーには取得できるtrack-contextを添えます。非文字列引数はvalue-error、未定義トラックはreference-error、未知のGaucheエラーはそのまま通します。

`sxmml.compiler` は五つの手続きと二つのマクロを公開します。通常 MML とリズム MML のパーサーは xref:mml.adoc[`sxmml.mml`]、登録先の状態は xref:environment.adoc[`sxmml.environment`] を参照してください。パーサー、generator、マクロの動作は Gauche 0.9.15 に従います。

== 手続き

`sxmml-compile-string!` 系は MML を sxmml IR の列へコンパイルし、`ctx` と合わせて二つの値を返します。`ctx` の解析状態はパーサーによって更新されます。トラックへの登録はここでは行わず、`mml` / `rhythm` マクロが `sxmml-ir-register!` を呼びます。文字列以外の入力は明示的なエラー、PEG の `<parse-error>` はトラック名を含む構文エラーとして投げ直します。

PEG の失敗種別 `type` が `fail-error` で、失敗情報 `objects` がタグと単一の `(fail-message . 文字列)` の構造なら、その文字列にトラック情報を付けます。たとえば `$raise` で伝えた未登録命令の理由は `sxmml syntax error: unknown MML command "x" on G track` となります。タグの値や理由の文言には依存しません。それ以外は残りの入力を使う既存の `sxmml syntax error, near "..." on G track` の表記を維持します。

[cols="2,4,4,1",options="header"]
|===
|書式 |引数と役割 |戻り値・前提・失敗条件 |ソース
|[[ref-compiler-sxmml-compile-mml-bang]]`(sxmml-compile-mml! str ctx)` |通常 MML 文字列と解析コンテキスト |`make-sxmml-mml-parser` を作って `sxmml-compile-string!` に渡す。二値を返す |link:../../sxmml/compiler.scm[compiler.scm]
|[[ref-compiler-sxmml-compile-rhythm-bang]]`(sxmml-compile-rhythm! str ctx)` |リズム MML 文字列と解析コンテキスト |`make-sxmml-rhythm-parser` を作って `sxmml-compile-string!` に渡す。二値を返す |link:../../sxmml/compiler.scm[compiler.scm]
|[[ref-compiler-sxmml-compile-string-bang]]`(sxmml-compile-string! parser str ctx)` |PEG パーサー、文字列、コンテキスト |パーサーが生成したオブジェクトのリストと `ctx` を返す。`str` が文字列でなければエラー。解析失敗は上記の明示的な理由、または入力付近を示すトラック名付き構文エラー |link:../../sxmml/compiler.scm[compiler.scm]

== ソース中で使うマクロ

両マクロはトラック名一つ、または一つ以上のトラック名のリストを受けます。`body ...` の Scheme 式は実行時に評価され、`write-tree` で文字列へ組み立てられます。複数トラックを指定した場合、各トラックの登録式をそれぞれ生成するため、本文の副作用もトラックごとに発生し得ます。未登録トラック、文字列化できない値、MML 構文エラーは登録時に失敗します。マクロ形式の詳細と利用例は xref:../sxmml-reference-manual.adoc[公開機能リファレンス]を参照してください。

[cols="2,4,4,1",options="header"]
|===
|書式 |引数と展開結果 |戻り値・副作用 |ソース
|[[ref-compiler-mml]]`(mml track body ...)` / `(mml (track ...) body ...)` |本文を通常 MML として `sxmml-compile-track-mml` に渡す式へ展開 |得たオブジェクト列を `sxmml-ir-register!` でトラックへ登録 |link:../../sxmml/compiler.scm[compiler.scm]
|[[ref-compiler-rhythm]]`(rhythm track body ...)` / `(rhythm (track ...) body ...)` |本文をリズム MML として `sxmml-compile-track-rhythm` に渡す式へ展開 |得たオブジェクト列を `sxmml-ir-register!` でトラックへ登録 |link:../../sxmml/compiler.scm[compiler.scm]
|===

== コンパイル例

リポジトリのルートで実行します。既定の解像度は 24 tick です。

[source,console]
----
$ gosh -I. -e '(use sxmml)' -e '(define-track G)' -e '(mml G "c8r8")' -e '(print (caar (slot-ref (sxmml-track-get (quote G)) (quote current-ticks))))'
24
----
