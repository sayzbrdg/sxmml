= `sxmml.backend.pmd` の生成処理
:toc: left

`sxmml.backend.pmd` には、PMD 向け MML の生成に使う 69 の定義と、LFO・エンベロープの規則の 4 つの表（`%pmd-lfo-types`・`%pmd-lfo-ranges`・`%pmd-envelope-types`・`%pmd-envelope-ranges`）があります。公開名はモード選択と生成の手続きで、`%` で始まる手続き、トラック状態のクラスとパラメータは内部で使います。パラメータ、オブジェクト、文字コード変換、一時ファイル、ファイル名操作は Gauche 0.9.15 の動作に従います。

生成系の `%pmd-...set!` 手続きは、特記しない限り `obj` を受けて現在の出力ポートへ PMD MML の文字列を書きます。名前の `set!` は文字列出力を含む内部の慣用名で、環境オブジェクトの slot を必ず変更するという意味ではありません。戻り値は生成側で使いません。必要なオブジェクト型と slot は xref:classes.adoc[クラス一覧]を参照してください。

PMD4 向けに利用するときは `pmd`、PMD3 向けには `pmd3` を指定します。以下は生成処理を保守するための内部定義の説明です。

音色値の `DT2` は OPN にはないパラメータです。`SEG` はハードウェアに存在する SSG-EG に関する値ですが、PMD は音色パラメータとして持ちません。共通の OPM・OPN クラスは両値を保持しますが、PMD 向け音色行には出力しません。出力先は `sxlc` が環境の `output` slot に設定し、`filename` メタデータは生成先に使いません。

== トラックとリズム行の組み立て

`%track-generate` は最適化された列を取得し、最頻の tick 数を既定音長として出力します。トラックのデータが空なら行を出しません。リズムの L トラックは定義用 R 行と配置用 K 行に分かれます。以下の手続きは現在の出力ポートへ書き、戻り値は呼び出し側で使用しません。

== PMD 生成例

リポジトリのルートで実行します。生成物は新しく作った一時ディレクトリに置きます。

[source,console]
----
$ scratch_dir=$(mktemp -d /tmp/sxmml-internal-pmd.XXXXXX)
$ SXMML_DOC_DIR="$scratch_dir" gosh -I. -e '(use sxmml.backend.pmd)' -e '(use sxmml)' -e '(sxmml-source-file (string-append (sys-getenv "SXMML_DOC_DIR") "/melody.sxl"))' -e '(pmd-source)' -e '(mml G "c8")' -e '(sxmml-pmd-source-generate)' -e '(let1 out (slot-ref (sxmml-environment) (quote output)) (print (sys-basename out) " " (file-exists? out)))'
melody.mml #t
----
