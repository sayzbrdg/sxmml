= `sxmml.backend.pmd` の共通処理
:toc: left

PMD両バックエンドで使う11個の公開手続き、FM採番用の公開クラス1件、非公開の定義値検査1件を持ちます。モード登録とファイル出力は xref:pmd-source.adoc[source]・xref:pmd-binary.adoc[binary]へ分離しています。

現在の登録環境を更新するのはsetup!だけです。FM音色の番号割り当ては出力ごとの採番状態を更新します。最適化要求の整数からどの処理を選ぶかは、このPMD共通層が決めます。CLIはその対応を解釈しません。

[cols="2,4,4,1",options="header"]
|===
|名前・書式 |役割・引数 |結果・状態・失敗条件 |ソース
|[[ref-pmd-sxmml-pmd-setup-bang]]`(sxmml-pmd-setup!)` |PMD共通の初期トラック登録 |現在の登録環境へA～J・Lを登録。FMのvolume-deltaは4、PCMは16 |link:../../sxmml/backend/pmd.scm[pmd.scm]

呼び出せない規則表は索引件数に含めません。`%pmd-lfo-types`・`%pmd-lfo-ranges`・`%pmd-envelope-types`・`%pmd-envelope-ranges`の4表で、従来の種類・個数・範囲を定めます。共通登録の検査は、手作りIRも受け取るバックエンドの検査の代わりにはしません。

== 手続きと構文

[[ref-pmd-sxmml-pmd-for-each-track-ir]]
`(sxmml-pmd-for-each-track-ir emit tracks env)`:: 固定パートの順に `(emit index part source track ir)` を呼ぶ。O9は逐次・並列とも元のIR列を渡し、各トラックの中で2候補を順に処理する。その他の反復圧縮を並列化するときは対象トラックの基本整理を先に行う。

[[ref-pmd-sxmml-pmd-output-tracks-select]]
`(sxmml-pmd-output-tracks-select env [backend])`:: 未対応音源を警告して除き、固定パートに対応するトラックを選び、音源種別を照合する。

[[ref-pmd-sxmml-pmd-pcm-voice-number]]
`(sxmml-pmd-pcm-voice-number env name)`:: PCMの定義名または従来の数値名をネイティブ番号へ解決する。

PMDの固定パート選択時、名前で補完するトラックと明示partのトラックが競合した場合は、パートと両名を示すvalue-errorとします。
