= `sxmml.mml` の手続きとパーサー
:toc: left

`sxmml.mml` は通常 MML とリズム MML のパーサーを定義します。`make-sxmml-mml-parser` と `make-sxmml-rhythm-parser` を公開し、その他の掲載項目はモジュール内部で使用します。`*note-command*` と `*rhythm-command*` はハッシュ表のため、手続きの項目には含めません。MML 文字列の構文は xref:../sxmml-mml-manual.adoc[MML コマンドマニュアル]を参照してください。

`$` で始まる項目の大半は Gauche `parser.peg` のパーサー値です。`define-inline` は値を常にマクロにする形式ではなく、ここでは手続きまたはパーサー値として働きます。各パーサーは PEG の入力状態を受ける手続きで、通常は直接呼ばず `make-sxmml-mml-parser` または `make-sxmml-rhythm-parser` から使用します。入力に一致しなければ PEG の失敗を返し、構文全体の解析失敗は呼び出し側でエラーになります。表の「結果」は一致時の値です。オブジェクト生成やパーサーの構築だけでは登録済みトラックは変更されません。`$note` などは解析コンテキストを変更します。

未登録の命令文字は、命令表の検索だけを `guard` で捕捉し、読んだ文字を含む理由を `$raise` に渡して回復不能な PEG の失敗とします。理由は `unknown MML command "x"` の形式で、トラック情報の付与は呼び出し側の `sxmml-compile-string!` が担当します。登録済みの命令パーサーの実行は、この捕捉の対象に含めません。

`define-inline`、Parameters、`parser.peg`、`$let`、`$return` は Gauche 0.9.15 の動作に従います。定義は表のソースファイル内で項目名から探せます。

== 音長計算例

リポジトリのルートで実行します。解像度 24 のとき、八分音符に付点一つを付けた長さは 18 tick です。

[source,console]
----
$ gosh -I. -e '(use sxmml.mml) (write (with-module sxmml.mml (length->ticks 8 1))) (newline)'
18
----
