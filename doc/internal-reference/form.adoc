= `sxmml.form` のエラー文脈とフォーム位置
:toc: left

`sxmml.form` の直下の手続きは8件で、7件を公開します。別に `report-additional-condition` のメソッドを1件定義します。`sxmml` 自体はこのモジュールを `extend` しません。定義・設定・加工マクロとcompilerが使い、エラーの意味は xref:classes.adoc#ref-classes-class-sxmml-error[エラーの分類]に従います。

フォーム位置は既存の「ファイル:行」文字列です。既知のエラーにだけ `<sxmml-source-context>` として添え、診断本文へ埋め込みません。トラックは別の `<sxmml-track-context>` なので、先に付いた別の情報を隠しません。同種の文脈が既にあれば内側のものを残します。

== 標準報告のメソッド

`(report-additional-condition (context <sxmml-source-context>) out)` は、指定ポートへ `    at ファイル:行` と改行を表示します。Gaucheの `report-error` がこのメソッドを使うため、ライブラリで標準報告を使う場合にもフォーム位置を確認できます。トラック文脈の報告メソッドは追加しません。CLIは既知のエラーについてこの標準報告を呼ばず、取得できる位置・トラック情報を診断本文に付けて標準エラーへ表示します。ライブラリのmessageには位置やトラックを埋め込みません。

== 使用例

既知の登録値の誤りは、value-errorとフォーム位置を別々に取り出せます。未定義のScheme変数やユーザー式の失敗は、form-errorやcauseに包まずGaucheへ任せます。マクロ展開自体の形式違反はform-syntax-errorです。ソース位置が不明な `eval` では、位置を推測して追加しません。
