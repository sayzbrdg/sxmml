= `sxmml.optimizer` のオブジェクト列最適化
:toc: left

`sxmml.optimizer` は四十七の手続きとクラス（record 型）三つを定義し、`sxmml-optimize-tree` を公開します。入力は登録済みトラックの `compiled-data` にある sxmml IR の列です。戻り値は平坦化されたオブジェクトのリストで、第 1 段階は元オブジェクトを変更せず、第 2 段階には休符の `ticks` を更新する処理があります。意味保持の判定原則は link:../verification.md#q-01-音楽的な意味の保持[検証方針]を参照してください。

`sxmml-optimize-tree` は先にトラックの `total-ticks` と `loop-ticks` を設定します。`:optimize #f` は無操作オブジェクトを除いて平坦化、真値は第 1 段階、`:full` は第 1 段階に加えて第 2 段階を適用します。`:repeat` は第 2 段階の後に、既存のリピートをひとまとめにして命令列を反復で圧縮し、`:repeat-expand` は展開後の長さが 256 以下の既存のリピートを展開してから圧縮します。圧縮は xref:repeat-tree.adoc[`sxmml.repeat-tree`] を使い、回数 2〜255、制御費用は `[ ]` が 2、`[ : ]` が 3、窓幅は `:repeat` が 256、`:repeat-expand` が 1024 です。展開すると反復の周期が延びるので、`:repeat-expand` は窓幅を広げます。回数の上限 255 と入れ子の上限 32 は PMD の局所ループの範囲です。最適化の目的は、コンパイル後のオブジェクトリストに連結されたオブジェクト数の削減です。バックエンドの最終文字列長は評価基準に含めません。オブジェクトとハッシュ表は Gauche 0.9.15 の動作に従います。

第 1 段階は区間を後ろから読み、設定ごとの効果をハッシュ表に蓄積します。効果は区間に入ったときの未知の値に対する絶対指定または相対差分であり、前の発音から実値を追跡するものではありません。後の絶対指定は先行する指定とその寄与位置を無効にし、相対指定は先行する絶対値または差分と加算します。例えば `v8 p1 v9` は `p1 v9`、`v9 p1 v*2` は `v11 p1` になります。

音量と移調は絶対・相対指定を共通の設定として扱います。`t` と `T` は同じテンポ設定で、最後の IR 型と値を残し、単位変換はしません。音色・ゲートタイム・パン・デチューン・エンベロープ・ノイズ周波数・出力切替は各設定の絶対指定です。LFO の選択と切替は別々に扱い、チャンネル省略 (`#f`) と `A` も別の鍵とします。切替値の `#f` は絶対指定として保持します。

リズム全体音量と楽器別音量を区別し、楽器別音量・パンは `bass`、`snare`、`tom`、`cymbal`、`hihat`、`rimshot` ごとに合成します。例えば `)bs2 vs9` は bass の相対差分 2 と snare の絶対値 9 になり、元の複数楽器指定の形には拘束されません。リズムの音量差 IR に全体音量の `value` がある場合は、単純な設定として合成せず境界として残します。

音符・休符・ポルタメント・リズム発音と消音、`L`、反復開始・脱出・終了、タイなどの単純な設定でない命令を境界とします。未知の IR も拒否せず境界として残し、境界を越えて設定を合成しません。NOP は除去します。出力順は寄与位置で決め、ハッシュ表の列挙順に依存しません。作業表と再構成中の IR は局所的に変更しますが、登録済み IR は変更しません。公開クラス `<sxmml-optimize-environment>` は維持しますが、第 1 段階の作業表には使用しません。第 2 段階以降の処理と入力変更の範囲は、この修正では変更していません。

== 第 2 段階の状態追跡

第 2 段階は通常音量・音色・ゲートタイム・パン・デチューン・エンベロープ・LFO 定義指定・LFO スイッチの 8 系統を追跡します。状態は既知の鍵だけを持つ連想リストとし、項目がなければ不明です。LFO の既知値 `#f` と不明、チャンネル省略と `A` を区別します。バックエンドの初期値は仮定しません。相対音量命令自体は残し、値が不明なら数値加算をせず不明を維持します。設定命令の合成や並べ替えはしません。

効果の要約は、変化なし・絶対指定・相対変化を表し、入口の状態とは別の情報です。脱出前の効果を F、脱出後を B、一周の効果を P=B∘F とすると、反復 n 回の効果は F∘P^(n−1) です。効果の累乗は絶対指定の維持または差分の乗算で求め、回数分の展開はしません。入れ子の要約は呼出しごとの作業用ハッシュ表で再利用します。

本文の最適化には、初回の状態 S と P(S) に共通する既知値を使います。この効果の範囲では、ここで一致する値は後続周回でも一致し、異なる値は不明とすれば全周回を含められます。1 回の反復には戻り経路がないので S だけを使います。出口は共通の入口ではなく、反復全体の要約を外側の S に適用して求めます。例えば `v8[v*1c8]3v9d8` では本文入口は不明でも出口は11と分かり、続く `v9` を残します。脱出地点の初回状態の保存・復元では代用しません。

L より前を一度実行した状態と、L から末尾までの効果で一周した状態を合わせて、L 以後を最適化します。`p1Lp1c8p2d8` では初回1と次周2が異なるので、L 直後の `p1` を残します。制御記号と回数は保持し、到達不能な命令を削除する新しい処理やリズム系の状態追跡は追加しません。公開クラス `<sxmml-optimize-2nd-pass-context>` は維持しますが、新しい処理には使用しません。

== 最適化例

次の入力では、最適化なしで二つの休符、第 2 段階で一つの休符になります。Gauche 0.9.15 を使い、sxmml のリポジトリルートで実行します。

[source,console]
----
$ gosh -I. -e '(use sxmml)' -e '(define-track G)' -e '(mml G "r8r8")' -e '(print (length (sxmml-optimize-tree (quote G) :optimize #f)))' -e '(print (length (sxmml-optimize-tree (quote G) :optimize :full)))'
2
1
----

`:repeat` の例です。既存のリピートの本文 `cccc` を `[c]4` に圧縮し、`:repeat-expand` では展開した `c` 八つを `[c]8` にします。最適化はオブジェクトを書き換えるので、水準ごとに別のプロセスで実行します。

[source,console]
----
$ gosh -I. -e '(use sxmml)' -e '(define-track G)' -e '(mml G "[c8c8c8c8]2")' -e '(print (length (sxmml-optimize-tree (quote G) :optimize :repeat)))'
5
$ gosh -I. -e '(use sxmml)' -e '(define-track G)' -e '(mml G "[c8c8c8c8]2")' -e '(print (length (sxmml-optimize-tree (quote G) :optimize :repeat-expand)))'
3
----
