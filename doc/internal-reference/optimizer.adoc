= `sxmml.optimizer` のオブジェクト列最適化
:toc: left

`sxmml.optimizer` は二十九の手続きとクラス（record 型）一つを定義し、`sxmml-optimize-tree` を公開します。入力は登録済みトラックの `compiled-data` にある MML オブジェクト列です。戻り値は平坦化されたオブジェクトのリストで、元オブジェクトの `value` や `ticks` を更新する処理もあります。意味保持の判定原則は link:../verification.md#q-01-音楽的な意味の保持[検証方針]を参照してください。

`sxmml-optimize-tree` は先にトラックの `total-ticks` と `loop-ticks` を設定します。`:optimize #f` は無操作オブジェクトを除いて平坦化、真値は第 1 段階、`:full` は第 1 段階に加えて第 2 段階を適用します。`:repeat` は第 2 段階の後に、既存のリピートをひとまとめにして命令列を反復で圧縮し、`:repeat-expand` は展開後の長さが 256 以下の既存のリピートを展開してから圧縮します。圧縮は xref:repeat-tree.adoc[`sxmml.repeat-tree`] を使い、回数 2〜255、制御費用は `[ ]` が 2、`[ : ]` が 3、窓幅は 256 です。回数の上限 255 と入れ子の上限 32 は PMD の局所ループの範囲です。最適化の目的は、コンパイル後のオブジェクトリストに連結されたオブジェクト数の削減です。バックエンドの最終文字列長は評価基準に含めません。オブジェクト、ハッシュ表、tree map は Gauche 0.9.15 の動作に従います。

蓄積用の `env` には xref:classes.adoc#ref-classes-class-sxmml-optimize-environment[`<sxmml-optimize-environment>`] を使用します。`object-*` は個別に呼ぶ公開 API ではなく、第 1 段階の状態更新を分担する手続きです。`lis` はコンパイル済みオブジェクトの列であり、文字列 MML ではありません。

== 最適化例

次の入力では、最適化なしで二つの休符、第 2 段階で一つの休符になります。Gauche 0.9.15 を使い、sxmml のリポジトリルートで実行します。

[source,console]
----
$ gosh -I. -e '(use sxmml)' -e '(define-track G)' -e '(mml G "r8r8")' -e '(print (length (sxmml-optimize-tree (quote G) :optimize #f)))' -e '(print (length (sxmml-optimize-tree (quote G) :optimize :full)))'
2
1
----

`:repeat` の例です。既存のリピートの本文 `cccc` を `[c]4` に圧縮し、`:repeat-expand` では展開した `c` 八つを `[c]8` にします。最適化はオブジェクトを書き換えるので、水準ごとに別のプロセスで実行します。

[source,console]
----
$ gosh -I. -e '(use sxmml)' -e '(define-track G)' -e '(mml G "[c8c8c8c8]2")' -e '(print (length (sxmml-optimize-tree (quote G) :optimize :repeat)))'
5
$ gosh -I. -e '(use sxmml)' -e '(define-track G)' -e '(mml G "[c8c8c8c8]2")' -e '(print (length (sxmml-optimize-tree (quote G) :optimize :repeat-expand)))'
3
----
