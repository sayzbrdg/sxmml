= 命名規約
:toc: left

== 適用範囲

この規約は、Gauche で記述された部分の識別子に適用する。製品コード、テスト、開発用ツールを対象とする。

他の言語や記法で記述された部分は、それぞれの慣習に従う。文書などで識別子を引用するときは、実際の綴りを用いる。

外部由来のモジュールは、由来元の命名慣習を尊重し、機械的に `sxmml-` を付けない。`repeat-tree` はその一例である。

== 基本表記

* 原則として小文字を用い、単語をハイフンで区切る。
* 正しい綴りを用い、同じ概念には同じ語を使用する。
* `mml`、`lfo`、`pmd`、`fm`、`opn` など、分野で通用する略語を使用する。
* 局所変数や引数には、意味が明確なら `ctx`、`res`、`vol`、`i`、`n` などの短い名前を使用できる。
* モジュール単位で定義する名前や export する名前は、意味が伝わる表記を優先する。
* 表の名前は、内容や対応関係を表す。表であることを明示する場合は、`command-table` のように `-table` を付ける。

== 名前空間と接頭辞

=== `sxmml-`

モジュール外から使用する一般の操作手続きには、原則として `sxmml-` を付ける。操作対象やバックエンドを表す語を選び、モジュール名を機械的に繰り返さない。

MML 記述者向けの名前は、MML 記述用の言語としての読みやすさを優先する。テスト用ヘルパーには `sxmml-` を要求しない。

=== `%`

export しない内部向けの名前であることを明示する場合に付ける。内部の名前すべてに付ける必要はない。

=== `$`

パーサー側の名前に付ける。MML コマンドに対応するものも、内部で使用するものも、小文字とハイフンで表記する。

単にパーサーを返すことだけで判断せず、その名前をパーサーとして用いるのか、パーサー構築の補助手続きとして用いるのかを区別する。

* `%$return`：内部向けのパーサーとして命名する。
* `%make-mml-value-parser`：解析用パーサー、クラス、変換手続きを組み込む構築補助手続きとして命名する。

`%` と `$` を併用する場合は、`%$` の順に付ける。

== 述語と `?`

真偽を判定する手続きには `?` を付け、正常終了時には `#t` または `#f` を返す。

真偽値を格納するスロットやレコードフィールドには `?` を付けず、真偽を判定するアクセサーには付ける。

局所変数や引数では、保持する値の性質を分かりやすく示すために、`pmd3?`、`has-loop?` などの表記を使用できる。

== 破壊的更新と `!`

引数として受け取ったデータを破壊的に更新する可能性のある手続きには、`!` を付ける。

暗黙の対象に対する明示的な設定・登録・削除・クリア操作でも、`!` の使用を許容する。

付与の判断は、操作対象と更新の性質に基づく。隠れた状態やキャッシュの更新、ファイルやポートへの出力、新しく構築する結果への初期設定だけを根拠に付けない。

パーサーは例外として、解析コンテキストを更新していても `!` を付けない。

== 構築・変換・その他の処理

=== 構築：`make-…`

名前の表す対象を構築し、使うために用意する手続きに使用する。新しい値を返すことや、戻り値の型だけでは判断しない。

たとえば、解析に使うパーサーを構築する手続きには `make-` を使用する。

export する構築手続きは、原則として `make-sxmml-対象` とする。

`mml.scm` で定義する構築手続き・構築用マクロは、次のように統一する。

[cols="1,2",options="header"]
|===
|公開範囲 |表記
|export するもの |`make-sxmml-…`
|export しないもの |`%make-…`
|===

他モジュールの内部構築補助は、使われ方に応じて判断する。

=== 変換：`元\->先`

型や概念上の表現の変換として、自然に読める場合に使用する。言語上の型が変わることは必須としない。

例：

* `%track\->track-list`：トラック指定をリスト形式に揃える。
* `%message\->located-message`：位置情報付きメッセージに変換する。
* `sxmml-bpm\->timer-b`：BPM と分解能からタイマー B の値に変換する。

=== 算出・整形など

処理自体が中心となる場合は、その処理を表す動詞を使用する。

例：

* `sxmml-pmd-voice-number-table-compute`：音色番号の割り当てを求める。
* `%mml-repeat-end-format`：反復回数を埋め込み、MML の反復終端表記を整形する。

`compile`、`optimize` など、処理内容を表す動詞も使用する。一般の生成処理は、Scheme の Generator と区別し、構築・変換・算出などの役割に応じて命名する。

== 操作を表す語

[cols="2,3",options="header"]
|===
|操作 |表記
|取得 |`対象-get`
|検索 |`対象-find`
|指定値の設定 |`対象-set!`
|現在値に基づく更新 |`対象-update!`
|個別の削除 |`対象-delete!`
|容器を空にする |`対象-clear!`
|通常の出力 |`対象-output`
|===

通常の出力処理には `output` を用いる。`write` は Scheme の読み書きを連想させるため、出力処理全般の名称として一律に使用しない。

取得・検索で値が見つからない場合の振る舞いや検索件数は、各手続きの仕様で定める。

== クラス・スロット・フィールド・parameter

* クラス名とレコード型名は `<対象>` とする。
* アクセサーは `対象-属性`、述語アクセサーは `対象-属性?` とする。
* 更新用アクセサーは、操作に応じて `対象-属性-set!`、`対象-属性-update!` などとする。
* スロットやフィールドには内容を表す名前を付ける。クラス名や `sxmml-` を繰り返す必要はない。
* parameter は保持する対象や役割に基づいて命名し、一律に `-parameter` を付けない。

== 用語と文章中の表記

* sxmml のコンパイル後の中間表現は、識別子内では `ir` と表す。
* 文書で区別・強調が必要な場合は、「sxmml IR」または「sxmml中間表現」と明示する。
* 第2パスは、識別子内では `2nd-pass` と表す。
* `portamento`、`gate-time` の表記を使用する。
* 歴史的な名称と実際の処理指定は、文脈に応じて使い分ける。PMD 関連の識別子における `shift-jis` と、文字コード変換指定の `cp932` が該当する。
* 識別子を引用するときは実際の綴りを用い、通常の文章では `LFO` などの一般的な表記を使用する。

== MML 記述者向けの名前

export の有無と、MML 記述者による使用を意図しているかどうかは、分けて判断する。

名前の変更時には、MML 記述者による使用を意図した名前かを確認し、互換性への影響を判断する。クラスやスロットに技術的にアクセスできることだけで、利用者向けの名前とは判断しない。
