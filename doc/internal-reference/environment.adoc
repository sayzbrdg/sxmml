= `sxmml.environment` の状態管理
:toc: left

楽曲のコンパイルに使う環境パラメータ、モードの登録と選択、メタデータ、LFO、エンベロープ、トラックおよび IR の登録表を管理します。

実装は link:../../sxmml/environment.scm[environment.scm] にあります。このモジュールは 40 定義（手続き 34 件・マクロ 6 件）を持ち、そのうち 36 定義（手続き 30 件・マクロ 6 件）を公開します。呼び出せない共有ハッシュ表（`%sxmml-modes`）は索引の掲載対象外です。

パラメータ、マクロ、ハッシュ表の動作は Gauche 0.9.15 に従います。MML 記述者向けの使い方は xref:../sxmml-reference-manual.adoc[MML 記述者向けリファレンス]を参照してください。

== 状態モデルとエラー分類

状態を保持する本体は xref:classes.adoc#ref-classes-class-sxmml-environment[`<sxmml-environment>`] です。`make-parameter` で作る束縛は手続きであり、引数なしで現在値を返し、値を 1 つ渡すと動的な現在値を変更して旧値を返します。

表への登録手続きは、特記しない限り現在の環境オブジェクト内のスロットまたはハッシュ表を変更します。登録手続きの戻り値は規定しません。未登録キーを取得したときの挙動は表ごとに異なります。

* `sxmml-metadata-get`・`sxmml-track-get`: `#f` を返します。
* `sxmml-option-get`: `undefined` を返します。
* `sxmml-lfo-get`・`sxmml-envelope-get`: Gauche のハッシュ表検索エラーになります。

エラーは用途に応じて分類します。

* 独自マクロの構文違反や引数形の誤り: `<sxmml-form-syntax-error>`
* 値・型・重複の違反: `<sxmml-value-error>`
* 未登録のモードやトラックの参照: `<sxmml-reference-error>`

マクロ経由の呼び出しでは、取得できるフォーム位置を既知の `<sxmml-error>` にだけ `<sxmml-source-context>` として添えます。値の式で生じた未定義変数や引数個数違反など Gauche 由来の例外は包み直さずそのまま送出します。

== 基本環境とオプション

[[ref-environment-sxmml-environment]]
=== `(sxmml-environment [env])`

現在の楽曲環境を保持するパラメータです。初期値は新規の `<sxmml-environment>` インスタンスです。引数なしで現在の環境を返し、`env` を渡すと動的な現在値を切り替えます。

[[ref-environment-sxmml-source-file]]
=== `(sxmml-source-file [path])`

入力ソースファイル名を保持するパラメータです。初期値は `#f` です。出力ファイル名の決定時などに参照します。

[[ref-environment-sxmml-resolution-get]]
=== `(sxmml-resolution-get)`

現在の環境の `resolution` スロット（四分音符あたりの tick 数）を返します。既定値は `24` です。

[[ref-environment-sxmml-resolution-set-bang]]
=== `(sxmml-resolution-set! resolution)`

現在の環境の `resolution` スロットを正の整数 `resolution` に設定します。整数でない値、0、負数を渡すと `<sxmml-value-error>`（`invalid resolution: <値> (expected a positive integer)`）を送出します。

[[ref-environment-sxmml-resolution]]
=== `(sxmml-resolution resolution)`

`sxmml-resolution-set!` の別名です。同じ値検査と状態変更を行います。

[[ref-environment-sxmml-default-output-path-get]]
=== `(sxmml-default-output-path-get)`

ソースから設定した既定出力先をそのまま返します。初期状態または `#f` で解除した後は `#f` です。`-o` オプションを含めて解決した最終出力先ではありません。

[[ref-environment-sxmml-default-output-path-set-bang]]
=== `(sxmml-default-output-path-set! path)`

現在の環境の `default-output-path` スロットを設定します。`path` には文字列または `#f` を指定します。最後に指定した値を採用し、`#f` で解除します。文字列でも `#f` でもない場合は `<sxmml-value-error>`（`invalid default output path: <値> (expected a string or #f)`）を送出します。

[[ref-environment-sxmml-option-get]]
=== `(sxmml-option-get name)`

現在の環境の `options` 表からシンボル `name` の設定値を取得します。シンボル名は大文字・小文字を区別します。未登録の場合は `undefined`、値が `#f` として登録されている場合は `#f` を返します。値はコピーせずそのまま返します。`name` がシンボルでない場合は `%option-name-check` により `<sxmml-value-error>` です。

[[ref-environment-sxmml-option-set-bang]]
=== `(sxmml-option-set! name value)`

現在の環境の `options` 表へシンボル `name` と値 `value` を登録・置換します。値の型は制限しません。環境ごとに独立して保持され、モード変更でも維持されます。`name` がシンボルでない場合は `<sxmml-value-error>` です。

[[ref-environment-internal-option-name-check]]`(%option-name-check name)`::
設定名 `name` がシンボルであるかを検査する非公開手続きです。シンボル以外は `<sxmml-value-error>`（`invalid option name: <値> (expected a symbol)`）を送出します。`sxmml-option-get` と `sxmml-option-set!` が表へアクセスする前に呼びます。

== モードの登録と選択

モード定義は各バックエンドの読み込み時に共有ハッシュ表 `%sxmml-modes` へ登録し、楽曲環境（`<sxmml-environment>`）は現在選択中の `<sxmml-mode>` インスタンスだけを保持します。出力オプションの組み立ては xref:output.adoc[`sxmml.output`] が担当します。

`<sxmml-mode>` の各スロットの型は次のとおりです。

* `name`: 正式名を表すシンボル
* `aliases`: 別名シンボルのリスト
* `setup`: モード選択時に引数なしで呼ぶ手続き、または `#f`
* `backend`: `<sxmml-output-environment>` を 1 つ受けて `<sxmml-output-result>` を返す手続き
* `output-extension`: 既定の拡張子文字列、または `#f`

CLI の `-m` とソース内の `sxmml-mode` マクロの双方で指定した場合は CLI 側を優先します。一方、明示的な `sxmml-mode-select!` による切り替えは `sxmml-mode-fixed` の値にかかわらず実行できます。全体の優先順位と実行順は xref:../behavior-spec.adoc#入力と実行順[外部動作仕様]を参照してください。

[[ref-environment-sxmml-mode-fixed]]
=== `(sxmml-mode-fixed [flag])`

モードが CLI などで確定済みかを示すパラメータです。初期値は `#f` です。真の間はソース内の `sxmml-mode` マクロによるモード選択を警告付きで無視します。`sxlc` は `-m` 指定時に真にしてソースを読み込みます。

[[ref-environment-sxmml-mode-register-bang]]
=== `(sxmml-mode-register! mode)`

`<sxmml-mode>` インスタンス `mode` を共有表 `%sxmml-modes` へ登録します。インスタンスの型、各スロットの型（必須項目の未設定を含む）、および登録済みモード名・別名との衝突を全件検査してから共有表を更新するため、失敗時は共有表を変更しません。手続きの引数個数は事前検査せず、`setup` も登録時には実行しません。

違反時は次の本文を持つ `<sxmml-value-error>` を送出します。

* `invalid mode: <値> (expected a <sxmml-mode> instance)`
* `invalid mode name: <値> (expected a symbol)` / `invalid mode name: <名前> (already registered for <既存モード名>)`
* `invalid mode aliases: <値> (expected a list of symbols)`
* `invalid mode setup: <値> (expected a procedure or #f)`
* `invalid mode backend: <値> (expected a procedure)`
* `invalid mode output extension: <値> (expected a string or #f)`

[[ref-environment-sxmml-mode-find]]
=== `(sxmml-mode-find name)`

正式名または別名のシンボル `name` で共有表 `%sxmml-modes` を検索し、一致する `<sxmml-mode>` を返します。未登録なら `#f` です。`name` がシンボルでない場合は `%mode-name-check` により `<sxmml-value-error>` です。

[[ref-environment-sxmml-mode-list]]
=== `(sxmml-mode-list)`

共有表 `%sxmml-modes` に登録されている `<sxmml-mode>` のリストを返します。別名による重複は `eq?` で除きます。返される順序は規定しません。

[[ref-environment-sxmml-mode-get]]
=== `(sxmml-mode-get)`

現在の環境で選択中の `<sxmml-mode>` を返します。未選択なら `#f` です。

[[ref-environment-sxmml-mode-selected-p]]
=== `(sxmml-mode-selected? name)`

正式名または別名のシンボル `name` が現在の選択モードと一致するかを返します。未登録または未選択・別モードの場合は `#f` です。`name` がシンボルでない場合は `<sxmml-value-error>` です。

[[ref-environment-sxmml-mode-select-bang]]
=== `(sxmml-mode-select! name)`

正式名または別名のシンボル `name` でモードを検索し、現在の環境の `mode` スロットを更新したうえで、`setup` が手続きなら引数なしで実行します。同じモードを再選択した場合も `setup` を再実行します。

`name` がシンボルでない場合は `<sxmml-value-error>`、未登録の場合は `<sxmml-reference-error>`（`undefined mode: <name>`）となり、現在の環境は変更しません。`setup` の実行途中で例外が送出された場合、それまでに完了した状態変更と `mode` スロットの更新はそのまま残ります。

[[ref-environment-sxmml-mode]]
=== `(sxmml-mode name)`

モード名 `name` を評価せずクオートして選択する公開マクロです。引数個数の誤りは `invalid sxmml-mode form: expected (sxmml-mode mode)`、`name` が識別子でない場合は `invalid sxmml-mode name: <値> (expected a symbol)` の `<sxmml-form-syntax-error>` になります。

正常時は、展開時に取得したフォーム位置を添えて `sxmml-form-wrap` で包んだ `(%sxmml-mode-select 位置 'name)` へ展開します。

[[ref-environment-internal-mode-name-check]]`(%mode-name-check name)`::
モード名 `name` がシンボルであるかを検査する非公開手続きです。シンボル以外は `<sxmml-value-error>`（`invalid mode name: <値> (expected a symbol)`）を送出します。

[[ref-environment-internal-sxmml-mode-select]]`(%sxmml-mode-select location name)`::
`sxmml-mode` マクロの非公開展開先です。`(sxmml-mode-fixed)` が真のときは、現在選択中モードの正式名を用いて `sxmml-form-warn-at` で `sxmml-mode in source is ignored; mode is already set to <name>` の警告を表示して無視します。偽のときは `(sxmml-mode-select! name)` を呼びます。

== メタデータ

[[ref-environment-sxmml-metadata-get]]
=== `(sxmml-metadata-get key)`

現在の環境の `metadata` 表から `key` を検索して返します。未登録なら `#f` です。

[[ref-environment-sxmml-metadata-set-bang]]
=== `(sxmml-metadata-set! key value)`

現在の環境の `metadata` 表へ `key` と `value` を登録します。同じ `key` が登録済みの場合は上書きします。

[[ref-environment-define-metadata]]
=== `(define-metadata key value)`

`key` を小文字化したシンボルへ変換し、`value` を式として評価して `sxmml-metadata-set!` へ渡す公開マクロです。`key` は識別子のみを受け付けます（違反は `invalid define-metadata key: <値> (expected a symbol)` の `<sxmml-form-syntax-error>`）。引数個数が一致しない場合は `invalid define-metadata form: expected (define-metadata key value)` の `<sxmml-form-syntax-error>` です。

`value` が 1 要素以上の文字列だけのリストである旧書式 `(define-metadata key ("a" ...))` は、展開時に `sxmml-form-warn` で非推奨の警告を表示し、文字列のリスト `(list "a" ...)` として登録します。登録の呼び出しは `sxmml-form-wrap` で包みます。値の型検査は行わず、各バックエンドが参照時に検査します。

== LFO・エンベロープの登録

`define-lfo` と `define-envelope` は共通の展開手続き `%define-lfo/envelope-expand` を使います。定義名は `sxmml-form-name\->symbol` でシンボル・識別子または数値から正規化し、種類 `type` は識別子として検査してシンボルへ変換します（省略時は `default`）。

値引数は、先頭が標準束縛の `list`・`quote`・`quasiquote` であるリスト、またはペア・空リスト以外の式（変数参照やリテラルなど）を新書式として扱い、1 つの式としてそのまま評価します。これら以外のプロパーリスト（空リストや一般の手続き呼び出し形を含む）は旧書式として扱い、展開時に `sxmml-form-warn` で位置付きの非推奨警告を表示して `(list 要素 ...)` へ展開します。

登録手続き `sxmml-lfo-set!`・`sxmml-envelope-set!` は、未使用の定義も含めて登録時に値がプロパーリスト（空リストを含む）であることを検査し、違反時は `<sxmml-value-error>` を送出して既存値を保持します。要素の個数や値の範囲は各バックエンドが参照時に検査します。

[[ref-environment-sxmml-lfo-get]]
=== `(sxmml-lfo-get id)`

現在の環境の `lfo` 表から `id` に対応する `<sxmml-lfo>` を返します。未登録の場合は Gauche のハッシュ表検索エラーになります。

[[ref-environment-sxmml-lfo-set-bang]]
=== `(sxmml-lfo-set! id type data)`

`<sxmml-lfo>` を生成して現在の環境の `lfo` 表へ登録・上書きします。`data` がプロパーリストでない場合は `<sxmml-value-error>`（`invalid LFO values: <id> is <data> (expected a proper list)`）を送出し、既存値を保持します。

[[ref-environment-define-lfo]]
=== `(define-lfo id [type] value)`

LFO を登録する公開マクロです。`%define-lfo/envelope-expand` にマクロ名 `"define-lfo"` と登録手続き `'sxmml-lfo-set!` を渡して展開します。

[[ref-environment-sxmml-envelope-get]]
=== `(sxmml-envelope-get id)`

現在の環境の `envelope` 表から `id` に対応する `<sxmml-envelope>` を返します。未登録の場合は Gauche のハッシュ表検索エラーになります。

[[ref-environment-sxmml-envelope-set-bang]]
=== `(sxmml-envelope-set! id type data)`

`<sxmml-envelope>` を生成して現在の環境の `envelope` 表へ登録・上書きします。`data` がプロパーリストでない場合は `<sxmml-value-error>`（`invalid envelope values: <id> is <data> (expected a proper list)`）を送出し、既存値を保持します。

[[ref-environment-define-envelope]]
=== `(define-envelope id [type] value)`

エンベロープを登録する公開マクロです。`%define-lfo/envelope-expand` にマクロ名 `"define-envelope"` と登録手続き `'sxmml-envelope-set!` を渡して展開します。

[[ref-environment-internal-define-lfo-envelope-expand]]`(%define-lfo/envelope-expand form rename id=? name set-proc)`::
`define-lfo` と `define-envelope` の共通展開を行う非公開手続きです。3 引数形では `type` を `default` とし、4 引数形ではリストでない `type` を受け付けます。`id` は `sxmml-form-name\->symbol`、`type` は `identifier?` で検査します（`type` 違反は `invalid <name> type: <値> (expected a symbol)`）。
+
値式は `id=?` で標準の `list`・`quote`・`quasiquote` を判別し、新書式はそのまま、旧書式は警告を出して `(list ,@value)` として `set-proc` の呼び出しを組み立て、`sxmml-form-wrap` で包みます。形式違反や非プロパーリストの値式は `invalid <name> form: expected (<name> id [type] value)` の `<sxmml-form-syntax-error>` です。

== トラック表と IR の登録

各トラックの状態は xref:classes.adoc#ref-classes-class-sxmml-mml-context[`<sxmml-mml-context>`] に格納し、現在の環境の `track` 表でトラック名と対応付けます。トラックとパートの対応はコンテキストの `part` スロットで保持し、`eq?` で比較します。

登録時に `:part` を省略すると `#f` になり、明示的に指定された `#f` 以外のパートだけを対象に重複を検査します。トラックの削除や全消去を行うと、そのトラックが使っていたパートは再利用できます。コンテキストや `track` 表を直接書き換えてパートの一対一対応を崩した場合、検索時の候補選択と生成物の再現性は保証しません。

[[ref-environment-sxmml-track-get]]
=== `(sxmml-track-get track)`

現在の環境の `track` 表から `track` に対応する `<sxmml-mml-context>` を返します。未登録なら `#f` です。

[[ref-environment-sxmml-track-set-bang]]
=== `(sxmml-track-set! track . params)`

初期化引数 `params` から新しい `<sxmml-mml-context>` を生成し、`track` 表へ登録・置換します。同じトラック名が登録済みの場合は新しいコンテキストで置き換え、以前の設定・IR・パートは引き継ぎません。不正な初期化引数は `make` で失敗します。

登録前に次の 2 点を検査し、違反時は `<sxmml-value-error>` を送出して `track` 表を変更しません。

* `:sound-source`: シンボルまたは `#f` であること（違反は `invalid track <track> sound-source: <値> (expected a symbol or #f)`）。
* `:part`: `#f` 以外が指定された場合、自身以外のトラックに同じパートが割り当てられていないこと（違反は `invalid track <track> part: <値> (already assigned to track <所有者>)`）。

[[ref-environment-sxmml-track-rename-bang]]
=== `(sxmml-track-rename! old-name new-name)`

登録済みトラックの名前を `old-name` から `new-name` へ変更します。同じ `<sxmml-mml-context>` インスタンスの `track` スロットを書き換えて `track` 表のキーを付け替えるため、パート・設定・IR・コンパイル状態はすべて保持されます。

* `old-name`・`new-name` がシンボルでない場合: `<sxmml-value-error>`（`invalid rename-track source/destination: <値> (expected a symbol)`）
* `old-name` が未登録の場合: `<sxmml-reference-error>`（`undefined track: <old-name>`）
* `new-name` が登録済み（同名を含む）の場合: `<sxmml-value-error>`（`invalid rename-track destination: <値> (already registered)`）

検査に失敗した場合は既存の状態を変更しません。

[[ref-environment-sxmml-track-delete-bang]]
=== `(sxmml-track-delete! track)`

現在の環境の `track` 表から `track` を削除します。

[[ref-environment-sxmml-track-clear-bang]]
=== `(sxmml-track-clear!)`

現在の環境の `track` 表からすべてのトラックを削除します。引数は取らず、引数を渡すと arity エラーになります。1 件だけ削除する場合は `sxmml-track-delete!` を使います。

[source,console]
----
$ gosh -I. -e '(use sxmml)' -e '(define-track (G H))' -e '(print (sort (map symbol->string (sxmml-track-list))))' -e '(sxmml-track-clear!)' -e '(print (sxmml-track-list))' -E exit
(G H)
()
----

[[ref-environment-sxmml-track-list]]
=== `(sxmml-track-list)`

現在の環境に登録されているトラック名（キー）のリストを返します。定義順や名前順を含め順序は保証しません。順序が処理結果に影響する箇所では、呼び出し側で必要な順序に並べ替えます。

[[ref-environment-sxmml-track-find]]
=== `(sxmml-track-find part)`

現在の環境の `track` 表から、`part` が真かつ `part` スロットが `eq?` で一致する最初のトラック名を返します。一致するトラックがない場合や `part` が `#f` の場合は `#f` です。

[[ref-environment-sxmml-ir-register-bang]]
=== `(sxmml-ir-register! ir track)`

登録済みトラック `track` のコンテキストにある `compiled-data` スロットへ IR 列 `ir` を追加します。`compiled-data` が空リストなら `ir` をそのまま格納し、すでにデータがある場合は `(cons 既存データ ir)` として cons 木で連結します。`track` が未登録の場合は何もしません。

[[ref-environment-define-track]]
=== `(define-track track param ...)` / `(define-track (track ...) param ...)`

1 つまたは複数のトラックを登録する公開マクロです。各トラック名は識別子として検査し（違反は `invalid define-track name: <値> (expected a symbol)` の `<sxmml-form-syntax-error>`）、`sxmml-form-wrap` で包んだ `(sxmml-track-set! 'track param ...)` へ展開します。

複数形式では次の制約と順序で動作します。

* 空リスト `(define-track () param ...)` は `define-track requires at least one track name` の `<sxmml-form-syntax-error>` になります。
* `param ...` に `:part` が含まれる場合は登録前に `invalid define-track form: :part requires a single track` の `<sxmml-form-syntax-error>` になります。
* 指定したトラック名の順に `begin` で展開し、パラメータ式はトラックごとに評価します。途中のトラック登録で失敗しても、先行して成功した登録は残ります。

[[ref-environment-rename-track]]
=== `(rename-track old-name new-name)`

トラックの登録名を変更する公開マクロです。引数個数の誤りは `invalid rename-track form: expected (rename-track old-name new-name)`、`old-name`・`new-name` が識別子でない場合は `invalid rename-track source/destination: <値> (expected a symbol)` の `<sxmml-form-syntax-error>` になります。

正常時は、展開時に取得したフォーム位置を添えて `sxmml-form-wrap` で包んだ `(sxmml-track-rename! 'old-name 'new-name)` へ展開します。
