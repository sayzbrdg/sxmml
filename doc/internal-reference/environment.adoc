= `sxmml.environment` の状態管理
:toc: left

`sxmml.environment` には環境と登録表を操作する 26 の定義があり、そのうち 24 を公開します。パラメータ、マクロ、ハッシュ表の動作は Gauche 0.9.15 に従います。MML 記述者向けの使用例は xref:../sxmml-reference-manual.adoc[公開機能リファレンス]を参照してください。

状態を保持する本体は xref:classes.adoc#ref-classes-class-sxmml-environment[`<sxmml-environment>`] です。`make-parameter` で作る束縛は手続きであり、引数なしで現在値を返し、値を一つ渡すと動的な現在値を変更して旧値を返します。表の設定手続きは、特記しない限り現在の環境オブジェクト内の slot または表を変更します。登録手続きの戻り値は呼び出し側では使用していません。`get` の未登録時の挙動は項目ごとに異なります。

`sxmml-mode` の呼び出し先を選ぶ処理は、backend モジュールが読み込まれていることを前提とします。CLI とソースの双方でモードを指定した場合は CLI 側が優先されます。動作は link:../behavior-spec.md#入力と実行順[外部動作仕様]を参照してください。

== LFO・エンベロープの登録

`define-lfo` と `define-envelope` は、共通の `%define-lfo/envelope-expand` で展開し、実行時に対応する `set!` 手続きを呼びます。`type`（LFO・エンベロープの種類。波形の種類）はリテラルのシンボルで、省略すると `default` です。枠の中の値は式として評価し、`(list 値 …)` を登録します。形は展開時に検査し、誤りは xref:form.adoc[`sxmml.form`] の `sxmml-form-error` で定義の位置を付けて投げます。値の式の誤りも、`sxmml-form-call` が定義の位置を付けた `<sxmml-form-error>` にします。未登録 ID の取得は、`get` に既定値を渡していないためハッシュ表の検索エラーになります。

|[[ref-environment-sxmml-lfo-get]]`(sxmml-lfo-get id)` |ID で LFO を検索 |登録済み `<sxmml-lfo>` を返す。未登録なら検索エラー |link:../../sxmml/environment.scm[environment.scm]
|[[ref-environment-sxmml-lfo-set-bang]]`(sxmml-lfo-set! id type data)` |LFO オブジェクトを作り登録 |`lfo` 表の `id` を上書き |link:../../sxmml/environment.scm[environment.scm]

|[[ref-environment-sxmml-envelope-get]]`(sxmml-envelope-get id)` |ID でエンベロープを検索 |登録済み `<sxmml-envelope>` を返す。未登録なら検索エラー |link:../../sxmml/environment.scm[environment.scm]
|[[ref-environment-sxmml-envelope-set-bang]]`(sxmml-envelope-set! id type data)` |エンベロープオブジェクトを作り登録 |`envelope` 表の `id` を上書き |link:../../sxmml/environment.scm[environment.scm]

== トラック表と登録済みオブジェクト

各トラックは xref:classes.adoc#ref-classes-class-sxmml-mml-context[`<sxmml-mml-context>`] に格納されます。`track` と `part` は別の slot です。トラック名をリストで指定する `define-track` は複数の context を作り、`:part` 未指定なら各トラック名を part に設定します。

[cols="2,4,4,1",options="header"]
|===
|名前・書式 |引数と役割 |結果・副作用・失敗条件 |ソース
|[[ref-environment-sxmml-track-get]]`(sxmml-track-get track)` |名前でトラックを検索 |未登録なら `#f` |link:../../sxmml/environment.scm[environment.scm]
|[[ref-environment-sxmml-track-set-bang]]`(sxmml-track-set! track . params)` |`:part` などの初期化引数から context を作る |`track` 表の同名項目を上書き。不正な初期化引数は `make` で失敗 |link:../../sxmml/environment.scm[environment.scm]
|[[ref-environment-sxmml-track-delete-bang]]`(sxmml-track-delete! track)` |指定したトラックを削除 |`track` 表からその key を削除 |link:../../sxmml/environment.scm[environment.scm]
|[[ref-environment-sxmml-track-clear-bang]]`(sxmml-track-clear!)` |トラック表を全件削除 |引数なしで `track` 表を空にする。一件だけ削除する場合は `sxmml-track-delete!` を使う |link:../../sxmml/environment.scm[environment.scm]
|[[ref-environment-sxmml-track-list]]`(sxmml-track-list)` |現在の登録名を列挙 |key のリストを返す。順序は保証しない |link:../../sxmml/environment.scm[environment.scm]
|[[ref-environment-sxmml-track-find]]`(sxmml-track-find part)` |`part` slot が一致する最初のトラック名を探す |見つからなければ `#f` |link:../../sxmml/environment.scm[environment.scm]
|[[ref-environment-sxmml-sio-regist-bang]]`(sxmml-sio-regist! sio track)` |コンパイル済みオブジェクト列を登録 |登録済みなら context の `compiled-data` を更新。未登録なら更新しない |link:../../sxmml/environment.scm[environment.scm]
|[[ref-environment-define-track]]`(define-track track param ...)` / `(define-track (track ...) param ...)` |一つまたは複数のトラックを設定するマクロ |`sxmml-track-set!` 呼び出しへ展開。複数トラック形は非空リストに一致する。`(define-track ())` は `define-track requires at least one track name` のエラー |link:../../sxmml/environment.scm[environment.scm]
|===

`sxmml-track-clear!` は引数なしでトラック表を全件削除します。次の例では `G` と `H` の両方を削除します。

[source,console]
----
$ gosh -I. -e '(use sxmml)' -e '(define-track (G H))' -e '(print (sort (map symbol->string (sxmml-track-list))))' -e '(sxmml-track-clear!)' -e '(print (sxmml-track-list))'
(G H)
()
----

引数を渡すと arity エラーになります。
