# 検証方針と手順

この文書は sxmml の変更時に実施する検証手順と期待結果を示す。検証基準は Gauche 0.9.15。[要求仕様](requirements.md)、[外部動作仕様](behavior-spec.md)、[開発手順](developer-guide.md)と併せて使う。

## 検証の層

| 層 | 確認方法 | 確認する内容 |
| --- | --- | --- |
| モジュール別 | `make check`、`test.log` | 下表のモジュールごとの binding と動作検査。配置先が同じモジュールでも、単体だけを検査しているとは限らない |
| sxlc | `make check`、`test.log`（`test/test-sxlc.scm`） | 実際の CLI を使い、引数・モード・出力先・診断・終了値・後処理・入力保護・文字コードを確認する。独立した内部処理のユニットテストではない |
| 製品全体の結合 | `make check`、`test.log`（`test/test-integration.scm`） | pmd-source の失敗 4 件、pmd-binary の失敗 6 件、両モードの反復回数 0 の失敗 2 件で、終了・診断・既存ファイルやディレクトリ内容の保持を確認する。個々の書込み・置換・削除操作を独立に検査するものではない |
| 計測の道具 | `make check`、`test.log`（`tools/test-measure-optimize.scm`、`tools/` があるときだけ） | `tools/measure-optimize.scm` の既定の設定、列、オブジェクト数の合計、E と W の指定、変換の失敗の表示、一時ディレクトリを残さないこと、設定とソースの誤りの終了値 2 |
| 解析・中間オブジェクト | `sxmml-compile-mml!`、`sxmml-compile-rhythm!` と公開マクロの評価 | オブジェクト列・トラック文脈・合計 tick |
| CLI・生成物 | インストール済み `sxlc` で入力を変換 | 終了値、表示、生成先、CP932 の内容、後処理の引数 |
| 意味保持 | 最適化前後の列を解釈して比較 | 下記 Q-01 の時間配置・音高・状態変更 |
| 文書例 | README・入門・両マニュアルの例を実行 | 各例の期待結果 |

`make check` の成功時は終了値0、`test.log` の各検査が `ok`、末尾が `passed.` となる。単独実行の方法は[開発手順](developer-guide.md#テストの単独実行)を参照する。変換例と配置の手順は[開発手順](developer-guide.md#隔離したコピーでの確認)と[配布手順](release-guide.md)を使う。

通常・リズム MML の反復は、回数0の構文解釈時の拒否と、正の回数の意味・集計・状態を `test/test-mml.scm` で検査する。`test/test-integration.scm` の回数0の2件は、フロントエンドで失敗する入力によるCLIの終了値1・診断・既存出力保持の確認であり、バックエンドに不正な中間表現を直接渡す検査ではない。各モードで実施する必要性や重複の判断は #121 の配置整理に含めない。

pmd-source の使用音色出力の追加5件は、最適化なし・第1段階、SSG・PCM 指定との区別、複数トラックの参照集約と全本文の配置、PMD3 の終端を検査する。新しい環境でソース読込み・最適化・公開バックエンドによる生成を接続する試験であり、CLI の引数解析は検査しない。

Lの重複拒否は、フロントエンドと、実装が分かれた両バックエンドの通常・リズムの各経路を区別して検査する。バックエンドの4件はパーサーを通さずIRを登録し、解析コンテキストの `loop-exists` を初期値のままにする。pmd-sourceのリズムの1件では、R0からR1へ進んだ後の2個目で失敗し、既存出力を含むディレクトリの名前と内容が変わらず、一時ファイルが残らないことも確認する。

PMDバイナリの固定期待値は、現行出力の固定と、試験のコメントにMC.EXEとの照合が記載されたものを区別する。全てを照合済みとは扱わない。モジュールへの配置だけで単体試験が充足したとは扱わず、必要な保証の不足は [issue #9](https://github.com/sayzbrdg/sxmml/issues/9) 等に引き継ぐ。他モジュールを通ることだけでは不足と判定しない。

## R-03 オブジェクト数の削減

最適化の効果は、コンパイル後の平坦なIR列の要素数で評価する。バックエンドの最終文字列長を削減効果の判定に使わない。登録時の `compiled-data` の外側のリスト長は、入れ子を含み得るため比較値に使わない。対象の操作で期待する削減を代表条件で確認し、全入力で必ず要素数が減ることは求めない。意味保持はQ-01で別に確認する。

### 本体が提供する処理と既存テスト

個別処理は整列済みのIR列を受け取り、単独で実行できる。既存テストは、処理の入出力を直接確認するものと、PMDの選択規則や出力への接続を確認するものを使い分けている。

| 個別処理 | 公開手続き | `test/test-optimizer.scm`で直接確認する代表条件 |
| --- | --- | --- |
| 局所整理 | `sxmml-ir-optimize-local` | 絶対・相対音量の2命令を、合成した値の1命令にする。原型の付加情報と入力を保持する |
| 不要な再指定の除去 | `sxmml-ir-remove-redundant-settings` | 音量・休符・同じ音量・休符の列から後の音量を除き、二つの休符は結合しない |
| 休符結合 | `sxmml-ir-merge-rests` | 各6ticksの休符二つを12ticksの休符一つへ結合し、後の原型の付加情報を保持する |
| 反復圧縮 | `sxmml-ir-compress-repeats` | `[cdcdcdLcdcdcd]2`に相当するIRを`[[cd]3L[cd]3]2`へ圧縮し、Lを新しい反復の外に保つ |

標準組合せの`sxmml-ir-optimize`は、局所整理・不要な再指定の除去・休符結合を順に適用する。`sxmml-ir-optimize-with-repeats`はその結果に通常の反復圧縮を、`sxmml-ir-optimize-with-repeat-expansion`はその結果に小さい既存反復を展開する反復圧縮を適用する。後者は通常の反復圧縮済みの列から開始しない。

基本組合せのテストは、再指定の除去後に休符を結合した値と音長を直接確認する。反復圧縮付きの組合せは、PMDから呼び出して生成される反復構造を確認するテストもある。`tools/test-measure-optimize.scm`には、同じ入力のO2・O3・O4で最終IR数が18・11・9となる集計の検査がある。これは計測ツールの検査でもあり、個別処理の検査とは役割を区別する。

### PMDの要求値との対応

整数の最適化要求値から処理を選ぶのはバックエンドの責務である。PMD両バックエンドは共通の`sxmml-pmd-ir-optimize`を使い、CLIの`-O`に次のように対応する。

| PMDの要求値 | 選択する処理 |
| --- | --- |
| 0以下 | 整列済みのIR列をそのまま返す |
| 1 | 局所整理 |
| 2 | 基本組合せ |
| 3 | 通常の反復圧縮付きの組合せ |
| 4以上 | 小さい既存反復の展開を伴う反復圧縮付きの組合せ |

`test/test-optimizer.scm`はPMDの選択を通したIR列や生成物も確認する。`test/test-sxlc.scm`では`-O 2`・`-O 3`・`-O 4`・`-O 9`について、CLIの表示と生成物への反映を確認する。

同一入力を要求値ごとに独立したGaucheプロセスで評価し、整列化と`sxmml-pmd-ir-optimize`の結果の要素数を`length`で数える。要求値0では無操作オブジェクトを除く整列化だけを行い、最適化前の比較基準とする。

README の導入手順でインストールしたモジュールが読み込めるシェルで、次を実行する。PMD共通手続きへ渡す0～4は、CLIの-O 0～4に対応する。

```console
gosh -e '(use sxmml)' -e '(use sxmml.backend.pmd)' -e '(define-track G)' -e '(mml G "v8v8c8r8r8")' -e '(print (length (sxmml-pmd-ir-optimize (sxmml-ir-flatten (slot-ref (sxmml-track-get (quote G)) (quote compiled-data))) 0)))'
gosh -e '(use sxmml)' -e '(use sxmml.backend.pmd)' -e '(define-track G)' -e '(mml G "v8v8c8r8r8")' -e '(print (length (sxmml-pmd-ir-optimize (sxmml-ir-flatten (slot-ref (sxmml-track-get (quote G)) (quote compiled-data))) 1)))'
gosh -e '(use sxmml)' -e '(use sxmml.backend.pmd)' -e '(define-track G)' -e '(mml G "v8v8c8r8r8")' -e '(print (length (sxmml-pmd-ir-optimize (sxmml-ir-flatten (slot-ref (sxmml-track-get (quote G)) (quote compiled-data))) 2)))'
```

この例では順に `5`、`4`、`3` となる。要求値1の局所整理で重複音量指定を整理し、要求値2の基本組合せでは隣接する休符も結合する。八つの休符だけの入力 `r8r8r8r8r8r8r8r8` に置き換えると `8`、`8`、`1` となる。数値要求3・4も同じ形で数える。入力 `c8d8c8d8c8d8` は 数値要求2まで `6`、数値要求3と4 で `4`（`[cd]3`）、入力 `[c8c8c8c8]2` は 数値要求2まで `6`、数値要求3で `5`（`[[c]4]2`）、数値要求4で `3`（`[c]8`）となる。各入力・要求値で削減前後の数と対象の操作を記録する。

最適化処理は [`sxmml/optimizer.scm`](../sxmml/optimizer.scm)、`length` は [Gauche 0.9.15 Users’ Reference, 6.6.5 List accessors and modifiers](https://practical-scheme.net/vault/Gauche-0.9.15-refe.pdf)を参照する。

## Q-01 音楽的な意味の保持

Q-01 は、最適化前後で、sxmml がコンパイルした後のオブジェクトリストを解釈した結果の意味が等しいことを求める。バックエンドの先にいるドライバーがどう発音するかは対象外である。`-O` 別の文字列、オブジェクト列そのもの、ファイル長やオブジェクト数の一致を意味保持の判定には使わない。

例えば、八つの `r8` と一つの `r1`、`v117 v*2` と `v119` は、表記の違いだけで不一致と判定しない。PMD 向けの生成行 `l%12o4cr` と `o4c%12r%12` も同じ考え方の例である。生成行は sxmml の入力構文ではない。

Scheme入力全体を評価して比較する場合は、同じ入力を**独立したGaucheプロセス**で`-O 0`〜`-O 4`相当の条件で評価し、環境・トラック文脈・最適化された列を各回で採取する。公開最適化は入力を変更しない。Scheme入力全体の評価では登録環境への作用を混ぜず、同じ条件で独立して評価する。IR単位の比較では、比較基準と入力を別々に構築する。入力、モード、分解能、トラック、Gaucheの版を固定し、比較対象と対象外を明示する。現行の分岐は[`sxlc`](../sxlc.in)と[`sxmml/optimizer.scm`](../sxmml/optimizer.scm)を参照する。

IR単位の自動テストには、[`test/ir-meaning.scm`](../test/ir-meaning.scm)の`test.ir-meaning`モジュールを使う。同じ入力を別々に構築し、一方を比較基準、他方を最適化対象として同一プロセスで比較する。比較器は整列済みの有効なIR列二つを受け取り、登録環境やバックエンドの既定値を参照しない。

初期対応は単一トラックの通常音符・休符・絶対／相対音量・有限反復とする。反復は入れ子・途中脱出を含めて一命令ずつ実行し、最適化器の状態処理や反復構造化・展開ヘルパーを参照解釈器に流用しない。音符の開始tick・音高・音長・音量と、列終了時の総tick・音量への効果を比較する。初期音量は共通の記号として保持し、特定の初期値で偶然一致しても初期状態に対する効果が異なれば不一致とする。

`(compare-ir-meaning before after :step-limit 100000)`は、判定と詳細の二つの値を返す。

| 判定 | 内容 |
| --- | --- |
| `match` | 対応範囲の解釈が完了し、音符列・総tick・終了時の音量への効果が一致。詳細は`#f` |
| `mismatch` | 最初に確定した意味の相違。詳細は音符の番号・項目・両値、または終了時の項目・両値 |
| `undecided` | 未対応IR・実行上限・`L`の制限による未判定。詳細はその理由 |

各列の実行IR数を既定100000命令までに制限し、制御IRも実行ごとに数える。上限は引数で変更できる。未対応IRまたは上限へ達した場合でも、それ以前の観測から相違を確定できれば不一致とする。停止時刻より前の音符の欠落は確定した相違として扱い、同時刻以降の不明な後続は欠落と扱わない。途中の状態を終了状態として比較しない。

`L`は一巡と終了状態で部分判定し、相違があれば不一致、なければ無限の実行全体については未判定とする。音色・移調・パン・デチューン・テンポ・ゲート・タイ・LFO・エンベロープ・ポルタメント・リズムなどの未対応IRへ到達した解釈は停止する。同じ未対応IRが両方にあっても読み飛ばさない。不正なIRの診断を網羅するものではなく、予期しないGaucheの例外を未判定へ包み直さない。

自己検証は、手で構築したIRと手計算した期待値による解釈器6件と、三つの判定・詳細を確認する19件からなる。次の単独実行と`make check`で確認できる。

```console
gosh -I. test/test-ir-meaning.scm
```

最適化の意味保持は、次の4条件で`match`を期待する。表は直接構築するIRの内容をMMLで示した説明例である。

| 標準組合せ | 入力の説明例 | 確認する点 |
| --- | --- | --- |
| `-O 1`相当 | `v8c8v*2e8v*-2v9g8` | 指定順に音量8・10・9となる効果 |
| `-O 2`相当 | `v8[v*1c8]3v9d8` | 反復中は音量9・10・11、その後は9となる効果 |

`:repeat`と`:repeat-expand`には、出力を展開した列が圧縮前と同値なIRの並びであることを毎回確認する検査もある。これは参照解釈器による検査とは別に維持する。有限の代表条件の成功を、全IR・全入力の意味保持を実証したものとは扱わない。残る対応範囲・制約は[issue #8](https://github.com/sayzbrdg/sxmml/issues/8#issuecomment-6619002641)で管理し、削減効果はR-03として区別する。

### 100回反復による追加確認と採用
