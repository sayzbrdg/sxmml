# 名前

sxlc — Scheme で記述した sxmml ソースを変換する

# 書式

    sxlc [-D name value] [-m mode] [-O level] [-j jobs] [-o output] [-c command] [-w] [--] file
    sxlc -l | -h | -v

長い形式は `--define`、`--mode`、`--optimize`、`--jobs`、`--output`、`--command`、`--wsl`、`--list`、`--help`、`--version`。

# 説明

sxlc は *file* を Scheme ソースとして読み込み、トラックに登録された MML から生成物を作る。入力ファイルは一つだけ指定する。オプションは *file* より前に書き、*file* より後ろに引数があると使用法の誤りとなる。`-` で始まるファイル名は `--` の後に書く。

出力形式は PMD・FMP7・NSD.Lib 向け MML と PMD バイナリ。動作環境は Gauche 0.9.15。

ビルド・インストールの手順は [README](../README.md#最初の変換)を参照。入力には Scheme の式が含まれるため、信頼できるソースを指定する。

# オプション

**-D** *name* *value*, `--define` *name* *value*
:   利用者定義の設定値を渡す。名前はsymbolへ変換し、大文字・小文字を区別する。値はSchemeのデータとして読み、sxlcで評価しない。例えば`-D variant hard`はsymbol、`-D gain 9`は数値、`-D enabled '#f'`は偽、`-D balance '(8 9 10)'`はリストを登録する。シェルの引用は指定する側で行う。

    読み取りは Gaucheの`gauche.parseopt`の`e`変換に従い、値の先頭のデータを1個読む。例えば`-D gain '9 10'`は9になる。引数不足や読み取り時の構文エラーは使用法の誤りとして終了値2となる。

    複数回指定でき、同じ名前は最後の値を使う。`-m`との位置関係によらずモード初期設定前に登録され、ソースの`sxmml-option-get`で取得できる。ソースの`sxmml-option-set!`による後続の変更も有効。未登録名の取得は `undefined`であり、登録済みの `#f`と区別する。

**-m** *mode*, `--mode` *mode*
:   出力モードを選ぶ。正式名と別名のどちらでも指定できる。

    - PMD4 向け MML は `pmd-source`（別名 `pmd`、`pmd4-source`）、PMD3 向け MML は `pmd3-source`（別名 `pmd3`）。
    - PMD バイナリは `pmd-binary`（PMD4、別名 `pmd4-binary`）、または `pmd3-binary`（PMD3）。
    - FMP7 向け MML は `fmp7`、NSD.Lib 向け MML は `nsdlib`。いずれもソース内で音源種別を指定してトラックを登録する。

    省略時はソースで `(sxmml-mode pmd)` などと指定する。**-m** を指定すると、ソース内の `sxmml-mode` は警告を表示し、モードを変更しない。この場合も引数の個数と名前の型は検査する。モードを明示的に変更する手続き `sxmml-mode-select!` は有効。

    変換結果と警告には正式名を使う。**-m** に未登録名を渡すと `undefined mode: 名前` と表示し、終了値は 2。モードの初期設定に失敗した場合は 1。

**-O** *level*, `--optimize` *level*
:   最適化レベルを整数で指定する。既定値は 1。適用する処理はバックエンドが決める。

    PMD では、0 以下で通常の最適化を省き、1 で連続する設定命令を整理する。2 ではさらに設定の状態を追跡して冗長な再指定を除き、隣り合う休符をまとめる。3 では既存の反復をひとまとめにして命令列を反復圧縮する。4 以上（9 を除く）では、展開後の長さが 256 以下の反復を展開し、3 より広い範囲で圧縮する。圧縮で比較するのは命令の数である。

    PMDの `-O 9` は、基本整理（局所整理・状態追跡・休符結合）と有限反復の展開を両方の順序で適用し、それぞれ区間全体を探索する。トラックごとに出力IR数が少ない方を採用し、同数なら先に基本整理した方を使う。`L` を含む反復と同じ段に複数の `:` がある反復は展開しない。

    全幅探索の計算量は区間長の3乗、主要な表の容量は2乗に比例する。探索対象が3,072要素を超える最初の区間でトラックごとに警告を標準エラーに表示し、処理を続ける。中断するにはCtrl-Cを押す。応答がなければ繰り返し押す。Gaucheが探索中に強制終了した場合、pmd-sourceの出力先は置き換わらず、出力先ディレクトリに一時ファイルが残ることがある。

    個々の指定値が有効でも、展開後に隣接する相対指定を合成した値が出力形式の範囲を超えると変換エラーになる。例えばpmd-binaryのFMでは、`[v*127]2c` の相対音量は合成すると `+254` となり、1命令の上限 `+127` を超える。

    FMP7 は 2 以下で登録した命令順を保ち、3 で反復圧縮、4 以上で短い反復の展開後に圧縮する。9 を指定した場合も 4 と同じ。

    nsdlib は全レベルで整列済み IR を順に変換する。反復圧縮を呼ばず、ワーカー数による出力差もない。

**-j** *N*, `--jobs` *N*
:   同時に反復圧縮するトラック数の上限を正の整数で指定する。省略時は利用可能な論理 CPU 数の半分を切り捨てて1～4に収め、取得できなければ1とする。明示値は4を超えてもよい。PMD・FMP7 では O3 以上で適用する。空でない対象トラックが1本以下、または `-j 1` の場合は逐次処理する。

**-o** *output*, `--output` *output*
:   生成物を *output* に書き込む。ソースの既定値より優先する。省略した場合はソースの既定値を使い、それもなければ *file* の拡張子を、選んだモードの拡張子（PMD 向けは `.mml`、PMD バイナリは `.m`、FMP7 向けは `.mwi`、NSD.Lib 向けは `.nsd`）に替えたパスへ生成する。相対パスは現在のディレクトリを基準とする。選ばれた出力先が *file* と同じファイルになる場合は、ソースを上書きせず使用法の誤りとして終了値 2 で終了する。

**-c** *command*, `--command` *command*
:   生成後に *command* を起動し、出力名を後ろへ付ける。*command* の引用・エスケープは指定する側が行う。sxlc は *command* を引数に分割した後、出力名を一引数として追加する。**-w** を指定すると、Windows 形式に変換したパスを渡す。どちらの場合も、空白や `;` があっても一引数になる。**-w** を指定しない場合、後処理の標準出力と標準エラー出力は変換せずにそのまま出る。*command* の字句の誤り（閉じていない引用符など）は、変換の前に検出して使用法の誤りとする。後処理が 0 以外の終了値やシグナルで終了した場合や、起動できなかった場合は、標準エラー出力に通知して終了値 3 で終了する。変換は成功しているため生成物は残る。

**-w**, `--wsl`
:   **-c** と併用したとき、`wslpath -aw` で後処理へ渡す名前を Windows 形式のパスにし、後処理の標準出力と標準エラー出力を CP932 から変換して標準出力に表示する。WSL から Windows のツールを後処理に使うための指定である。CP932 として復号できないバイト列は置換文字に置き換える。`wslpath` が必要。`wslpath` が失敗した場合は終了値 3 で終了する。

**-l**, `--list`
:   登録済みモードの正規名と別名を表示して終了する。正規名順に並べ、別名は登録時の順序で同じ行に表示する。

**-h**, `--help`
:   使用法を表示して終了する。

**-v**, `--version`
:   パッケージのバージョンを表示して終了する。

# 入力と出力

生成先は **-o**、ソースの既定値、入力名とモードによる既定値の順に選ぶ。ソースでは `(sxmml-default-output-path-set! "song-hard.mml")` のように指定する。文字列または `#f` を受け取り、`#f` で解除する。相対パスは現在のディレクトリを基準とする。取得手続き `(sxmml-default-output-path-get)` はソースの指定をそのまま返し、初期値・解除後は `#f` となる。型が異なる値はソースの値エラーとして終了値1で報告する。設定値に応じた例は[公開機能リファレンス](sxmml-reference-manual.adoc#ソースの既定出力先)を参照する。

入力との同一性は採用する出力先について検査する。ソースの既定値が入力自身を指していても、**-o** で別のパスを指定すれば生成できる。生成後の `Translate` 行は実際の生成先を示す。PMD の各モードでは、ソース中の `(define-metadata filename "出力先")` は生成先の指定には使われず、警告 `warning: metadata 'filename' is ignored; use the -o option of sxlc to set the output file` を表示して無視される。

ファイルを生成しないバックエンドが出力先として `#f` を返した場合、`Translate` 行の表示と **-c** の起動を省く。

NSD.Lib 用は UTF-8（BOM なし）の MML を生成する。`sxlc -m nsdlib -c 'nsc -n' song.sxl` では、生成後に `nsc -n` を起動し、`song.nsd` の絶対パスを渡す。

PMD と FMP7 向けの MML は CP932、改行は CRLF。

変換に成功すると、モードと指定した最適化レベルを表示する。バックエンドが採用したトラックのうち tick 数が正のものについて合計 tick 数を表示する。ループ位置を指定したトラックでは loop の tick 数も表示する。外部ドライバーでの演奏時間を示す値ではない。

PMD バイナリのモード（`pmd-binary`、`pmd4-binary`、`pmd3-binary`）は外部コンパイラを使わずに PMD のバイナリを直接生成する。生成物が MC.EXE の出力と同じであることは保証しない（PMD 向け MML を MC.EXE でコンパイルした結果と一致するとは限らない）。同じ条件からはバイト単位で同じ生成物ができることと、失敗時の扱いは他のモードと同じ。

# 例

導入済みの `sxlc` が使えるシェルで次を実行する。

```console
printf '%s\n' '(mml G "c8r8")' > first.sxl
sxlc -m pmd first.sxl
iconv -f CP932 -t UTF-8 first.mml
```

最初の変換では `first.mml` が作られ、`Track G: total: 24` と表示される。

# 終了とエラー

**-h**、**-v**、**-l** は正常終了する。終了値は次のとおり。ソースが `exit` を呼んだ場合は、その値で終了する。

0
:   成功。**-c** を指定した場合は後処理も成功。

1
:   変換の失敗。ソースの読み込み・評価、MML、生成、出力先のエラー。

2
:   使用法の誤り。不正なオプションや引数、入力ファイル名なし、**-m** のモードを選べない、**-c** の字句の誤り、出力先が入力ファイルと同じ、*file* より後ろの引数。誤りの内容を標準エラー、使用法を標準出力へ表示する。

3
:   後処理の失敗。**-c** の後処理が 0 以外の終了値やシグナルで終了した、起動できなかった、**-w** の `wslpath` が失敗した。

モードが CLI とソースの双方で未指定ならエラーとなる。未登録トラック、不正な MML、未定義の FM 音色なども変換に失敗する。変換に失敗した場合は終了値 1 で終了し、出力先の既存ファイルを変更せず、途中までの生成物を残さない。診断と終了値は[外部動作仕様](behavior-spec.adoc#失敗条件と境界値)を参照。

既知の入力エラーは `sxlc: error: 本文` の形で標準エラーへ表示する。取得できるフォーム位置は本文の前へ、トラックは末尾へ付け、Gaucheの例外見出しやスタックトレースを付けない。未知のGaucheエラー・I/O・内部の失敗はGaucheの標準報告を維持する。使用法は、使用法の誤りの場合も標準出力へ表示する。

既知の問題の対応状況と詳細は [既知の課題（GitHub の issue）](https://github.com/sayzbrdg/sxmml/issues)を参照。
