= 検証方針と手順

この文書は sxmml の変更時に実施する検証方針・テスト構成・期待結果を示す。検証基準は Gauche 0.9.15 とする。xref:requirements.adoc[要求仕様]、xref:behavior-spec.adoc[外部動作仕様]、xref:developer-guide.adoc[開発・改修手順] と併せて使う。

[[検証の層]]
== 検証の層

[cols="1,2,3",options="header"]
|===
|層 |確認方法 |確認する内容
|モジュール別 |`make check`、`test.log` |下表のモジュールごとの binding 検査と動作検査。配置先が単一モジュール名であっても、他モジュールや CLI を経由して観測する検査を含む
|CLI（`sxlc`） |`make check`、`test.log`（`test/test-sxlc.scm`） |実際の CLI を使い、引数・モード・出力先・`-D`・`-O`・診断・終了値・後処理・入力保護・文字コードを確認する
|製品全体の結合 |`make check`、`test.log`（`test/test-integration.scm`） |PMD（source・binary）および FMP7 で失敗する入力に対し、0 以外の終了値・診断・既存ファイルやディレクトリ内容の保持を確認する

[[r-03-オブジェクト数の削減]]
== R-03 オブジェクト数の削減

最適化の効果は、コンパイル後の平坦な IR 列の要素数で評価する。バックエンドの最終文字列長は削減効果の判定に使わない。登録時の `compiled-data` の外側のリスト長は入れ子を含み得るため比較値に使わない。対象の操作で期待する削減を代表条件で確認し、全入力で必ず要素数が減ることは求めない。意味保持は Q-01 で別に確認する。

[[本体が提供する処理と既存テスト]]
=== 本体が提供する処理と既存テスト

個別処理は平坦化済みの IR 列を受け取り、単独で実行できる。既存テストは、処理の入出力を直接確認するものと、バックエンドの選択規則や出力への接続を確認するものを使い分けている。

[cols="1,2,3",options="header"]
|===
|個別処理 |公開手続き |`test/test-optimizer.scm` で直接確認する代表条件
|局所整理 |`sxmml-ir-optimize-local` |絶対・相対音量の 2 命令を合成した値の 1 命令にする。原型の付加情報と入力を保持する
|不要な再指定の除去 |`sxmml-ir-remove-redundant-settings` |音量・休符・同じ音量・休符の列から後の音量を除き、2 つの休符は結合しない
|休符結合 |`sxmml-ir-merge-rests` |各 6 ticks の休符 2 つを 12 ticks の休符 1 つへ結合し、後の原型の付加情報を保持する
|反復圧縮 |`sxmml-ir-compress-repeats` |`++[cdcdcdcdLcdcdcdcd]2++` に相当する IR を `++[[cd]4L[cd]4]2++` へ圧縮し、`L` を新しい反復の外に保つ
|===

標準組合せの `sxmml-ir-optimize` は、局所整理・不要な再指定の除去・休符結合を順に適用する。`sxmml-ir-optimize-with-repeats` はその結果に通常の反復圧縮を、`sxmml-ir-optimize-with-repeat-expansion` はその結果に小さい既存反復を展開する反復圧縮を適用する（後者は通常の反復圧縮済みの列から開始しない）。

基本組合せのテストは、再指定の除去後に休符を結合した値と音長を直接確認する。反復圧縮付きの組合せは、バックエンドから呼び出して生成される反復構造を確認するテストも持つ。`tools/test-measure-optimize.scm` には、同一入力の `O2`・`O3`・`O4` で最終 IR 数が `21`・`11`・`9` となる集計検査がある。

[[pmdの要求値との対応]]
=== PMD の要求値との対応

整数の最適化要求値から処理を選ぶのはバックエンドの責務である。PMD 両バックエンドは共通の `sxmml-pmd-ir-optimize` を使い、CLI の `-O` に次のように対応する。

[cols="1,3",options="header"]
|===
|PMD の要求値 |選択する処理
|0 以下 |平坦化済みの IR 列をそのまま返す
|1 |局所整理
|2 |基本組合せ（局所整理・不要再指定の除去・休符結合）
|3 |通常の反復圧縮付きの組合せ
|9 |基本整理と有限反復展開の順を変えた 2 候補の全幅圧縮
|9 を除く 4 以上 |小さい既存反復の展開を伴う反復圧縮付きの組合せ
|===

`test/test-optimizer.scm` は PMD の選択を通した IR 列や生成物も確認する。`test/test-sxlc.scm` では `-O 2`・`-O 3`・`-O 4`・`-O 8`・`-O 9`・`-O 10` について、CLI 表示と生成物への反映を確認する。`-O 9` の検査では休符の展開順で出力 IR 数が変わる入力、同数時の選択、展開を保留する反復、警告の境界、複数トラックの逐次・並列出力の一致を扱う。

同一入力を要求値ごとに独立した Gauche プロセスで評価し、平坦化と `sxmml-pmd-ir-optimize` の結果の要素数を `length` で数える。要求値 0 では NOP を除く平坦化だけを行い、最適化前の比較基準とする。

README の導入手順でインストールしたモジュールが読み込めるシェルで次を実行する。

[source,console]
----
gosh -e '(use sxmml)' -e '(use sxmml.backend.pmd)' -e '(define-track G)' -e '(mml G "v8v8c8r8r8")' -e '(print (length (sxmml-pmd-ir-optimize (sxmml-ir-flatten (slot-ref (sxmml-track-get (quote G)) (quote compiled-data))) 0)))' -E exit
gosh -e '(use sxmml)' -e '(use sxmml.backend.pmd)' -e '(define-track G)' -e '(mml G "v8v8c8r8r8")' -e '(print (length (sxmml-pmd-ir-optimize (sxmml-ir-flatten (slot-ref (sxmml-track-get (quote G)) (quote compiled-data))) 1)))' -E exit
gosh -e '(use sxmml)' -e '(use sxmml.backend.pmd)' -e '(define-track G)' -e '(mml G "v8v8c8r8r8")' -e '(print (length (sxmml-pmd-ir-optimize (sxmml-ir-flatten (slot-ref (sxmml-track-get (quote G)) (quote compiled-data))) 2)))' -E exit
----

この例では順に `5`、`4`、`3` となる。要求値 1 の局所整理で重複音量指定を整理し、要求値 2 の基本組合せでは隣接する休符も結合する。その他の代表入力は次のとおりである。

* `r8r8r8r8r8r8r8r8`: 要求値 0・1 で `8`、要求値 2 で `1`
* `c8d8c8d8c8d8c8d8`: 要求値 2 まで `8`、要求値 3・4 で `4`（`++[cd]4++`）
* `++[c8c8c8c8c8c8]2++`: 要求値 2 まで `8`、要求値 3 で `5`（`++[[c]6]2++`）、要求値 4 で `3`（`++[c]12++`）
* `++[c8c8c8c8]2++`: 要求値 3 まで `6`、要求値 4 で `3`（`++[c]8++`）

最適化処理は link:../sxmml/optimizer.scm[`sxmml/optimizer.scm`]、`length` は link:https://practical-scheme.net/vault/Gauche-0.9.15-refe.pdf[Gauche 0.9.15 Users' Reference, 6.6.5 List accessors and modifiers] を参照する。

[[q-01-音楽的な意味の保持]]
== Q-01 音楽的な意味の保持

Q-01 は、最適化前後で、sxmml がコンパイルした後のオブジェクトリストを解釈した結果の意味が等しいことを求める。バックエンドの先にいるドライバーがどう発音するかは対象外である。`-O` 別の文字列、オブジェクト列そのもの、ファイル長やオブジェクト数の一致を意味保持の判定には使わない。

たとえば、8 つの `r8` と 1 つの `r1`、`++v117 v*2++` と `v119` は表記の違いだけで不一致と判定しない。PMD 向けの生成行 `l%12o4cr` と `o4c%12r%12` も同じ考え方の例である（生成行は sxmml の入力構文ではない）。

Scheme 入力全体を評価して比較する場合は、同じ入力を独立した Gauche プロセスで `-O 0`～`-O 4` 相当の条件で評価し、環境・トラック文脈・最適化された列を各回で採取する。IR 単位の自動テストには、link:../test/ir-meaning.scm[`test/ir-meaning.scm`] の `test.ir-meaning` モジュールを使う。同じ入力を別々に構築し、一方を比較基準、他方を最適化対象として同一プロセスで比較する。比較器は平坦化済みの有効な IR 列 2 つを受け取り、登録環境やバックエンドの既定値を参照しない。

初期対応は単一トラックの通常音符・休符・絶対／相対音量・有限反復とする。反復は入れ子・途中脱出を含めて 1 命令ずつ実行し、最適化器の状態処理や反復構造化・展開ヘルパーを参照解釈器に流用しない。音符の開始 tick・音高・音長・音量と、列終了時の総 tick・音量への効果を比較する。初期音量は共通の記号として保持し、特定の初期値で偶然一致しても初期状態に対する効果が異なれば不一致とする。

`(compare-ir-meaning before after :step-limit 100000)` は、判定と詳細の 2 つの値を返す。

[cols="1,3",options="header"]
|===
|判定 |内容
|`match` |対応範囲の解釈が完了し、音符列・総 tick・終了時の音量への効果が一致。詳細は `#f`
|`mismatch` |最初に確定した意味の相違。詳細は音符の番号・項目・両値、または終了時の項目・両値
|`undecided` |未対応 IR・実行上限・`L` の制限による未判定。詳細はその理由
|===

各列の実行 IR 数を既定 100,000 命令までに制限し、制御 IR も実行ごとに数える。上限は引数で変更できる。未対応 IR または上限へ達した場合でも、それ以前の観測から相違を確定できれば不一致とする。停止時刻より前の音符の欠落は確定した相違として扱い、同時刻以降の不明な後続は欠落と扱わない。途中の状態を終了状態として比較しない。

`L` は 1 巡と終了状態で部分判定し、相違があれば不一致、なければ無限の実行全体については未判定とする。音色・移調・パン・デチューン・テンポ・ゲート・タイ・LFO・エンベロープ・ポルタメント・リズムなどの未対応 IR へ到達した解釈は停止する。同じ未対応 IR が両方にあっても読み飛ばさない。予期しない Gauche の例外は未判定へ包み直さない。

自己検証は、次の単独実行と `make check` で確認できる。

[source,console]
----
gosh -I. test/test-ir-meaning.scm
----

`test/test-optimizer.scm` では、次の標準組合せ 4 条件で `match` を確認する（表は直接構築する IR の内容を MML で示した説明例）。

[cols="1,2,3",options="header"]
|===
|標準組合せ |入力の説明例 |確認する点
|`-O 1` 相当 |`++v8c8v*2e8v*-2v9g8++` |指定順に音量 8・10・9 となる効果
|`-O 2` 相当 |`++v8[v*1c8]3v9d8++` |反復中は音量 9・10・11、その後は 9 となる効果
|`-O 3` 相当 |`c8d8c8d8c8d8c8d8` |反復圧縮前後の音符と時間配置
|`-O 4` 相当 |`++[c8c8c8c8]2++` |既存反復の展開・再圧縮前後の意味
|===

反復圧縮の試験では、`test/repeat-tree-check.scm` で木の費用・回数・展開を、`test/optimizer-repeat-check.scm` で復元した IR 列の一致を明示的に検査する。有限の代表条件の成功を、全 IR・全入力の意味保持を実証したものとは扱わない。残る対応範囲・制約は link:https://github.com/sayzbrdg/sxmml/issues/8[issue #8] で管理し、削減効果は R-03 として区別する。

[[文書例と境界値の確認]]
== 文書例と境界値の確認

link:../README.md#最初の変換[README の導入手順] で配置した `sxlc` とモジュールを使う。各入力を別のファイルに保存し、変換前に同名の出力が存在しない状態で、終了値・生成内容・合計 tick を確認する。

[cols="2,3",options="header"]
|===
|入力・操作 |期待結果
|`(mml G "c8r8")` を `-m pmd` で変換 |終了値 0、G は 24 tick、`G l%12o4cr`、ヘッダー `PMDver4.8`
|README の `phrase.sxl` |終了値 0、G は 60 tick
|同じ入力を `-m pmd3` で変換 |ヘッダー `PMDver3.3`、末尾 `0x1A`
|通常音符・休符・リズム発音・リズム休符・ポルタメントで `%01`、`%00012` |1 tick と 12 tick。ゼロ埋めを除いた入力と同じ結果
|`8&%01`、`%01&%00012` |合計 13 tick
|`%0`、`%00`、`8&%00` |正の整数が必要というエラー、終了値 1、新規出力なし
|`define-track (G H)` の後に無引数の `sxmml-track-clear!` |トラック名の一覧が `()`
|`(define-track ())` |トラック名が必要というエラー
|`-o` に空白入り生成名を指定して `-c` で引数を表示 |実際の生成先が 1 引数で渡り、`Translate` 表示と一致する
|===

`-w` と後処理の組み合わせは、`wslpath` のある環境で Windows 形式のパスと引数個数、後処理の CP932 の出力が UTF-8 に変換されて表示されることを確認する。`make check` は引数をそのまま返すモック `wslpath` を用意して出力の変換だけを確かめ、実際のパスの変換は確かめない。生成物を実際の Windows ツールへ渡す確認は、パス変換の確認とは別に行う。
