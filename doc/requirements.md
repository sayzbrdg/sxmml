# sxmml 要求仕様

この文書は sxmml の製品要求と実装状態を示す。動作環境は Gauche 0.9.15 である。製品の目的・利用者・境界は[製品概要](product-overview.md)を参照する。

## 製品要求

| ID | 要求 | 判定の観点 | 実装箇所 |
| --- | --- | --- | --- |
| R-01 | Scheme を使い、古い MML の制約に妨げられず柔軟に MML を記述できる | 現行実装で再現できる記述例と制約 | [`sxmml/compiler.scm`](../sxmml/compiler.scm) の `mml` / `rhythm`、[`sxlc.in`](../sxlc.in) のソース読み込み |
| R-02 | Scheme から MML オブジェクトを操作できる | 現行実装で利用者が操作できる対象・方法・結果 | [`sxmml/classes.scm`](../sxmml/classes.scm) の MML クラス、[`sxmml/processor.scm`](../sxmml/processor.scm) の変換マクロ |
| R-03 | 既存ドライバー向け MML で手作業だった最適化を自動化できる | 現行実装が行う最適化の種類とコンパイル後のオブジェクト数の削減 | [`sxmml/optimizer.scm`](../sxmml/optimizer.scm) の `sxmml-optimize-tree`、[`sxlc.in`](../sxlc.in) の `-O` |
| R-04 | sxmml が変換結果の生成物を作る | 現行実装の入力・出力形式と生成結果 | [`sxmml/backend/pmd.scm`](../sxmml/backend/pmd.scm) の PMD 向け MML 生成、[`sxmml/backend/pmd-binary.scm`](../sxmml/backend/pmd-binary.scm) の PMD バイナリ生成（実験的） |

R-04 は生成物を MML に限定しない。現在の出力は PMD 向け MML と、実験的な PMD バイナリである。PMD バイナリは、生成物が MC.EXE の出力と同じであることを保証しない。生成先は `sxlc` の `-o` で指定し、生成先、CLI 表示、`-c` に渡す名前が一致することを要求する。ソースから生成先を変更する手段は設けない（`filename` メタデータは無視する）。

`-c` のコマンド文字列は指定者が引用・エスケープする。sxmml がその後ろに追加する生成ファイル名は、`-w` の有無にかかわらず一つの引数として後処理へ渡すことを要求する。空白や `;` を含む生成名も一引数で渡る。

R-01・R-02 については、Scheme 式で作った MML 文字列リストを `mml` に渡せる。MML オブジェクトの slot を直接変更することも可能だが、関連する文脈値は自動で更新されない場合がある。slot を直接編集する場合は、関連する文脈値も利用者が更新する必要がある。

`rhythm`、`mml-repeat`、`mml-echo`、`mml-delay` の基本形は利用できる。`mml-echo` は単一トラックを受け付ける。`mml-repeat` の三本文形式では第三節の本文を反復後に置く。`mml-delay` は音符の後の休符を対象とする。

MML ソース内では `define-track`、`sxmml-resolution`、`define-metadata`、`define-lfo`、`define-envelope`、`define-opn-voice`、`sxmml-mode pmd` の基本形を使える。`define-metadata` の値は式として評価する。PMD4 向けには `pmd`、PMD3 向けには `pmd3` を指定する。CLI とソース内のモード指定が重なると、CLI 側が優先される。定義値の生成物への反映は[外部動作仕様](behavior-spec.md)を参照する。

R-03 の最適化は、コンパイル後のオブジェクトリストに連結されたオブジェクト数を減らす処理である。バックエンドが出力する最終文字列の長さは評価基準に含めない。代表的な処理は、重複した音量指定の削減と連続休符の結合である。R-04 については、CP932 の PMD 向け MML ファイルを生成する。実験的な PMD バイナリのモードでは `.m` ファイルを生成する。

## 要求と現行実装の対応

具体的な構文・出力・エラーは[外部動作仕様](behavior-spec.md)を参照する。

| 要求 | 実装動作と関連仕様 | 要求との差・制約 | 実装状態 |
| --- | --- | --- | --- |
| R-01 | Scheme の `map` 等で作った MML 断片を `mml` に渡して音符を登録できる。[外部動作仕様](behavior-spec.md)。tick 指定はゼロ埋めした正の整数も受理し、0 は拒否する | `define-metadata` の旧書式（括弧の中に文字列だけを並べる形）は非推奨で、警告を出して受け付ける | Scheme 式による MML 記述を提供 |
| R-02 | `mml-repeat`・`mml-echo`・`mml-delay` で MML オブジェクトを加工する。[公開マクロ](sxmml-reference-manual.adoc) | slot の直接編集では文脈値が同期しない場合がある。複数トラックのエコーは、トラックごとに `mml-echo` を呼ぶ。[issue #6](https://github.com/sayzbrdg/sxmml/issues/6) | 加工マクロを提供、複数トラックの `mml-echo` は未実装 |
| R-03 | 重複音量指定の削減と休符の結合を自動で行う。[比較例](verification.md#r-03-オブジェクト数の削減) | 削減効果は入力に応じて評価する。意味保持は Q-01 として別に判定する | 水準別の最適化処理を提供 |
| R-04 | PMD モードで CP932 の `.mml` ファイルを生成する。実験的な PMD バイナリのモードで `.m` ファイルを生成する。[外部動作仕様](behavior-spec.md) | PMD バイナリは実験的であり、MC.EXE の出力と同じであることを保証しない。他形式は提供していない | PMD 向け生成と、実験的な PMD バイナリ生成を提供 |

現在残る不具合・未実装・検証不足・仕様確認待ちは [GitHub の issue](https://github.com/sayzbrdg/sxmml/issues)で課題ごとに参照できる。要求の内容と優先順位は本書で扱う。

## 判定方法

各要求の判定に使う入力、実行条件、期待結果は[検証方針](verification.md)に定める。

| 要求 | 動作の判定方法 | 判定対象・条件 |
| --- | --- | --- |
| R-01 | Gauche 0.9.15 で Scheme 式から MML 断片を作り、登録結果と制約を比較する | `mml` と各定義マクロを個別に評価する。入力の種類と失敗例は外部動作仕様に従う |
| R-02 | 対象ごとに操作前後の MML オブジェクトを照合し、関連する文脈値への影響も確認する | 公開加工マクロを対象とする。slot の直接編集時は関連する文脈値も比較する |
| R-03 | 同一入力を独立したプロセスで水準別にコンパイル・最適化し、返された平坦なリストのオブジェクト数を比較する | 最終文字列長は評価基準に含めない。意味保持は下記 Q-01 として別に判定する |
| R-04 | 入力とモードを固定して生成ファイルの有無、パス、符号化、内容を照合する | PMD 向け MML を対象とし、生成先・CLI 表示・後処理に渡す名前を比較する |

## 優先順位

R-01 の柔軟な MML 記述と R-02 の MML オブジェクト操作を、R-03 の最適化自動化より優先する。R-01 と R-02 の間の順位、および R-04 との順位は未定である。R-03 も製品の対象に含む。

## 境界・品質・互換性

* 製品の範囲は[製品概要](product-overview.md#責任範囲)に定める。
* 動作環境は Gauche 0.9.15 である。言語・ライブラリの仕様は [Gauche 0.9.15 Users’ Reference](https://practical-scheme.net/vault/Gauche-0.9.15-refe.pdf)に従う。
* **Q-01**: 最適化前後で、sxmml がコンパイルした後のオブジェクトリストを解釈した結果の意味が等しいことを要求する。バックエンドの先にいるドライバーの発音は判定対象に含めない。表記やオブジェクト列が異なっても、解釈した意味が等しければ保持されている。全入力での成立は未実証である。通常の最適化を避けるには `-O 0` を指定する。対応状況は [issue #8](https://github.com/sayzbrdg/sxmml/issues/8)を参照する。
* Q-01 の比較では、休符の連結、音量の相対指定と絶対指定、音長の既定値と明示指定など、異なる表記で等しい意味になる場合を扱う。比較方法は[検証方針](verification.md#q-01-音楽的な意味の保持)に定める。
* **Q-02**: ソースの読み込み、生成、出力先への書き込みのいずれかで変換が失敗し、`sxlc` がエラーとして終了する場合は、0 以外の終了値で終了し、出力先の既存ファイルを変更せず、途中までの生成物や一時ファイルを残さないことを要求する。対象は `sxlc` が出力先に書くファイルであり、ソース中の Scheme 式が自ら書き込むファイルや、強制終了など `sxlc` が処理できない中断は含めない。出力先が入力ファイルと同じ場合は変換を行わず、ソースを変更しない。`-c` の後処理の失敗は変換の失敗に含めず、生成物を残して別の終了値で示す。終了値の体系は[外部動作仕様](behavior-spec.md#失敗条件と境界値)に示す。個々の失敗条件は[外部動作仕様](behavior-spec.md#失敗条件と境界値)に示す。
* **Q-03**: 同じ入力ファイル（ファイル名を含む）、モード、最適化水準、sxmml と Gauche の版で変換した生成物が、バイト単位で一致することを要求する。生成物の意味の同一性はバックエンドの出力形式ごとに異なるため、全てのバックエンドに共通する条件として、意味ではなくバイト単位の一致を求める。バックエンドは、ハッシュ表の反復順など実行ごとに変わり得る順序に依存して出力してはならない。
